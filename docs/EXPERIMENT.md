# 실험 — 실제 빅카인즈 API 로 본 "대응 발언 이후의 후속보도" (v2 §4)

> 보도가 없다는 사실은 조치가 없었다는 근거가 아니라, 확인이 필요하다는 신호입니다.

멘토 피드백(2026-10-22): 합성 데이터가 아니라 실제 API 로, 사고 뒤 "이렇게 처리하겠다" 가 적힌 원천 기사부터 유니크하게 모으고,
같은 사건끼리 묶어 후속보도가 있었는지 정량 지표로 보일 것. 이 문서는 그 실험의 방법·호출 수·한계를 기록한다.
숫자는 실행할 때마다 `reports/experiment_<YYYYMMDD_HHMM>.md` 와 `reports/experiment_latest.json` 에 새로 쓰인다(아래 "결과" 는 그 요약).

## 1. 실행

```bash
cd backend
# 호출 계획만 (API 호출 없음)
BIGKINDS_MODE=record LLM_MODE=rules EMBEDDING_BACKEND=st .venv/bin/python scripts/experiment.py --stage all --dry-run
# 실제 실행 (record: 실호출 + 녹화, 같은 --today 로 다시 돌리면 녹화 재생)
BIGKINDS_MODE=record LLM_MODE=rules EMBEDDING_BACKEND=st .venv/bin/python scripts/experiment.py --stage all --today 2026-10-22 --max-pages 2
# 사람 라벨(CSV)을 채운 뒤 지표만 다시
.venv/bin/python scripts/experiment.py --stage report --today 2026-10-22
# 사람이 고친 시드로 수집 이후만 다시
BIGKINDS_MODE=record LLM_MODE=rules .venv/bin/python scripts/experiment.py --stage all --seeds seeds/events.yaml --today 2026-10-22
```

- `.env` 의 `TODAY_OVERRIDE=2026-09-11` 은 가상 픽스처용이다. 실험은 `--today`(기본: 오늘 KST)를 기준일로 쓰고 `.env` 는 바꾸지 않는다.
- 녹화 요청 키에 `published_at.until`(기준일 다음 날)이 들어가므로 재생은 같은 `--today` 로 한다. 녹화는 `backend/fixtures/bigkinds/recordings/`.
- 실험 DB 는 `DATABASE_URL` 기본값 `backend/data/migyeol.db`. 단계 중간 산출물은 `backend/data/experiment/`(discover.json · groups.json · state.json — 원문 인용문 포함, gitignore 대상).

## 2. 방법

### 2.1 원천 기사 (§4.2)
"원천 기사" = 사건 뒤 공공 주체가 대응·조치를 밝힌 발언이 인용된 기사.

1. **인용문 검색(주)** — `search/quotation`, `category_incident` = 사고>산업사고 / 사고>교통사고 / 재해>자연재해 각각, 질의
   `("하겠다" OR "할 계획" OR "추진" OR "마련" OR "전수조사" OR "보강" OR "점검" OR "설치" OR "교체" OR "재발 방지" OR "대책")`,
   기간 2023-01 ~ 2025-12 **월별 36구간 × 3계열 = 108구간**. 실서버는 (월, 계열)당 1만 건 이상을 돌려주므로(본문까지 매칭) `return_from` 상한 안에서
   `sort: {"_score": "desc"}` 상위 `--max-pages`(2) × 100건 = 구간당 200건을 받는다(전수 아님 — 표본. 3~4쪽째는 실서버 30초 타임아웃이 잦다).
2. 남기는 인용문: `source` 가 공공 주체(`rules/actors.is_public_actor`) · 규칙 어댑터가 **확약·계획**으로 본 발언(행동 동사 + 구체 행동) · 수사·감식 경위만인 발언 제외.
3. `news_ids` 상세 조회(100건씩)로 제목·본문 200자·분류를 받아 **제목에 재난 어휘**가 있고 해외 사건·국제면이 아닌 기사만 원천 기사로 본다.
4. **이슈 랭킹(보조)** — `issue_ranking(date)` 를 2023-01-01 ~ 2025-12-31 매일 순회. 토픽·토픽 키워드에 재난 어휘(침수·붕괴·화재·폭발·태풍·호우·산사태·지진·탈선·추락·매몰·전복·침몰·누출)가
   있는 토픽만 클러스터 앞 20건을 상세 조회해 3계열 비율 ≥ 0.3 이면 이슈 사건. 인용문 경로 사건과 (±14일, 시설 또는 지역 + 재난 계통)이 맞으면 '이슈 확인'(점수 +2),
   안 맞으면 (시설·지역 AND 재난어) AND 대응 발언 질의로 발생일 ~ +30일 인용문을 한 번 더 찾는다(상한 300건).

### 2.2 유니크화와 자동 시드 (§4.2-3·4)
- 같은 사건: 인용 기사일 ±14일 안에서 ① 같은 시설명, ② 같은 기초 지역 + 같은 재난 계통(물·붕괴·화재·교통·작업·기상), ③ 같은 정규화 기관 + 같은 재난 계통 + 지역이 겹치거나 둘 다 없음, ④ 같은 발언(전재). 대표는 가장 이른 기사.
- 점수: 제목이 실제 사고(참사·붕괴·침수·사망 …)를 가리키고 예방·계절 대비 기사가 아니면 +3, 예방·대비 기사 −4, 시설명 +2, 기초 지역 +2(광역만 +1), 확약 +1, 사상자 수 +1, 기관 확인 +1(없으면 −1), 기사 수 ×0.3(≤6), 이슈 확인 +2.
- 선택: (계열, 연도) 9개 층을 돌아가며 점수순으로 `--max-events`(150)개. 점수 2 미만은 다른 층이 모두 떨어졌을 때만.
- **질의 건수 보정**: 후보를 1.5배(225개) 고른 뒤 각 질의의 (발생일-1 ~ 기준일) `time_line` 총건수를 보고, 400건이 넘으면 (시설 AND 지역) → (재난어 2개 AND) → (사건 고유어 AND) 순으로 좁힌다.
  사건 고유어 = 그룹의 원천 기사 제목 2건 이상에 함께 나온 말 + 이슈 토픽 키워드(제목 한 건의 아무 단어로 좁히면 후속 기사가 다 빠진다). 상한 안으로 들어온 사건만 다시 층별로 150개 고른다.
  이유: collect 는 건수가 상한(사건당 600) 안이면 사건당 4회로 끝나지만, 넘으면 월·순별 '조치 상태 질의'로 사건당 100회 넘게 부른다(1차 시도에서 확인).
- `seeds/experiment.draft.yaml`: 기존 시드 형식 + `source_news_id`·`source_quotation`·`auto_seed: true`, 참고용 `_` 키(점수·발언 주체·강도·그룹 기사 등).
  `query` 는 (시설 OR 재난어) AND (지역 OR 기관 OR 별칭 OR 시설) — 수집과 인용문 검색이 같은 좁은 질의를 쓴다(인용문 검색이 본문까지 매칭해 OR 하나로는 너무 넓다).
- 실기사 문장(제목·인용문)은 단정 표현이 들어 있으면 가린다(`experiment/text.scrub`, 금지어 검사 대상이라서).

### 2.3 군집·후속보도 (§4.3·4.4)
- 기존 파이프라인 함수를 그대로 쓴다: collect(시드 질의, 초기 2주 + 이후 구간) → link(규칙 게이트 + `st` 임베딩 `jhgan/ko-sroberta-multitask`, LINK_AUTO 0.55 / LINK_REVIEW 0.40, 임계값 변경 없음) → extract(인용문 → 약속, rules-v1) → 약속 키워드 재검색 → 재연결 → judge(후속 신호 rules-v1 + 상태 규칙 R1~R5).
  실험 실행에만 쓰는 설정 사본: 사건당 수집 총상한 600(기본 300)·초기 구간 상한 300, LLM 호출 상한 해제(규칙 어댑터라 외부 호출 없음). `config.py` 기본값은 그대로다.
- **약속 키워드 재검색은 실험판**(`experiment/followups.py`)으로 바꿨다. 파이프라인 판은 추적 약속마다 (행동 명사 OR) AND (기관 OR 지역 OR 시설)을 따로 부르는데, 실데이터에서 '건축물'·'정밀점검' + 지역명만으로 수천 건이 걸려 약속 하나에 100회 넘게 나왔다(약속 748건 → 수만 회). 실험판은 사건당 한 질의 (상위 행동 명사 4개 OR) AND (지역 OR 시설 OR 지역 기관), `time_line` 건수 ≤ 400 일 때만 받는다(넘으면 재난어 AND, 그래도 넘으면 생략·기록).
- 규칙 어댑터 산출물(약속·신호)은 followup 단계마다 지우고 다시 만든다(결정적이고 호출 비용이 없다 — 규칙을 고친 뒤 옛 결과가 캐시로 남지 않게).
- 원천 기사는 수집 후보에 넣고, 게이트·임계값을 통과하지 못하면 `source-article` 사유로 확정 연결한다(사건을 정의하는 기사이므로). 리포트에 자동/확정 건수를 따로 적는다.
- **후속보도 있음** = 연결 기사 중 발행일 > max(발생일 + 7일, 원천 발언일)인 기사에서 유효 신호(완료·진행·새로운문제, 약속 일치, 신뢰도 ≥ 0.6)가 1건 이상. 경과 창 30/90/180/365일은 첫 유효 신호 기사일 기준 누적.
- 규칙 어댑터(rules-v1)는 LLM 이 없어 쓰는 대체물이다. 가상 픽스처 stub 정답과의 일치율: 약속 여부 100%(10건) · 강도 100% · 후속 신호 94%(18건) (`tests/test_rules_adapter.py`).

### 2.4 교차 검증 (§4.5)
- `backend/gold/experiment_labels.csv` — 사건별 시스템 판정(후속보도 있음/없음, 상태, 첫 후속 기사·신호·발췌) + 사람 열 `사람_후속보도(O/X)`·`사람_근거_news_id`·`사람_군집OK(O/X)`·`사람_기관명OK(O/X)`·`사람_메모`.
- `backend/gold/cluster_sample.csv` — 사건당 자동 연결(rule/embedding) 기사 무작위 5건(사건 키로 고정된 표본) + `사람_OK(O/X)`.
- `backend/gold/org_sample.csv` — 발언 주체 원문 → 정규화 기관 쌍(빈도순 300) + `사람_OK(O/X)`·`사람_정답`.
- 다시 내보내도 채운 사람 열은 보존된다. `--stage report` 가 라벨된 건수를 분모로 precision/recall·군집 정밀도·기관 정확도를 계산한다. `scripts/labels_to_gold.py` 는 라벨을 evaluate.py 정답셋 YAML 로 옮긴다.

## 5. 한계

- **표본**: 인용문 검색은 (월, 계열)당 1만 건 이상을 돌려준다(108구간 합계 588,647건). 대응 발언어 점수 상위 200건씩(21,600건)만 봤다. 원천 기사 1,559건은 모집단 전수가 아니다.
- **군집 잡음**: 연결 엔진·임계값은 예선 그대로다(지침). `st` 임베딩은 같은 지역·같은 재난어 기사끼리 유사도가 높아 다른 사건 기사가 자동 연결된다 → 후속보도 수를 부풀린다. `cluster_sample.csv` 라벨로 군집 정밀도를 잰 뒤 LINK_AUTO 스윕(`evaluate.py --sweep`)이 필요하다.
- **규칙 어댑터**: 약속 행동 키워드가 1개만 겹쳐도 신뢰도 0.65 로 유효 신호가 된다(명세 §5). LLM 이 아니라 문맥(누가 무엇을 끝냈는지)을 못 본다. 다른 표현을 쓰는 후속 기사는 '불명확'으로 빠진다.
- **질의 보정의 편향**: 건수 400건 안으로 좁혀지는 사건만 골랐다 → 전국 단위 대형 재난(전국 호우·산불 전체)보다 시설·지역이 특정되는 사건 쪽으로 기운다(후보 225 중 148이 상한 안).
- **약속 재검색 생략**: 150건 중 88건은 약속 키워드 질의가 400건을 넘거나 키워드가 없어 재검색을 건너뛰었다(기록).
- **기관 정규화**: 사전 기반. '시 관계자'·'김 지사' 처럼 기관을 특정할 수 없는 발언 주체는 원문 그대로 남는다(`org_sample.csv` 상위). 사건 책임기관은 원천 발언 주체에서 정하므로 '대통령실'·'국무총리' 같은 중앙 발언자가 책임기관이 되는 사건이 있다.
- **피해 규모**: 원천 기사 제목·본문 200자 정규식. '누적 사망자'처럼 사건 전체가 아닌 수치가 들어갈 수 있고, 없으면 null 이다.
- **기관 발표 확인**: 트랙 C 의 게시판 확인을 아직 실험 DB 에 돌리지 않아 0 이다(통합 단계).
- 보도가 없다는 사실은 조치가 없었다는 근거가 아니다. 후속보도 부족 50건은 확인이 필요한 사건 목록이다.

## 6. 가중치 개선 전후 (2026-10-24, 같은 라벨)

§5 의 "다음에 손볼 것" 1·2 를 **사건별 단어 가중치**와 **문장 가중치**로 다뤘다. 실 API 호출 없이 `link → followup → report` 만 녹화 재생으로 다시 돌렸다(바꾸기 전 DB 는 `backend/data/_backup/migyeol_before_weights_20261024.db`). 전체 표: `reports/eval_labels_20261024.md`.

**무엇을 바꿨나**
- `rules/weights.py`: 사건마다 TF-IDF 식 단어 가중치. TF = 핵심 문서(시드 문장 + 원천 기사 + 발생일 ±3일 게이트 통과 후보) 중 등장 비율, IDF = 기사 57,498건 전체 DF. 시설명·핵심어·질의 고유어는 하한 0.6(코퍼스에서 흔하면 제외 — '산사태'·'임야'), 지역명·일반 재난어·행정어는 상한 0.05. `events.term_weights` 에 저장, link 단계마다 재계산. 예: 통복터널 단전 사고 → 통복터널 1.0 · 민간자문단 0.87 · SRT 0.84 · 부직포 0.73 · 단전 0.6 …, '사고'·'터널'·'평택' 은 목록에 없다(상한·저빈도로 탈락).
- `link.py`: `weighted_overlap`(기사에 나온 사건 단어 가중치 합 / 상위 10개 합). 강한 규칙이 아니면 `≥ WEIGHT_MIN` 이어야 게이트 통과, 강한 규칙도 `< WEIGHT_RULE_MIN` 이면 강한 규칙에서 내린다. 점수 = (1-α)·임베딩 코사인 + α·weighted_overlap.
- `rules_adapter.py`(rules-v2): 제목·하이라이트·인용문 문장마다 관련도 = 약속 action 임베딩 코사인 + 사건 가중치 단어 점수. 상위 3문장 안에서만 완료·진행·새로운문제 표현을 보고, 약속 키워드가 없어도 사건 고유어 점수 ≥0.8 인 문장(제목 근거)은 후보로 둔다. confidence 에 관련도를 더한다.

**스윕 요약** (`WEIGHT_RULE_MIN × WEIGHT_MIN × WEIGHT_ALPHA × LINK_AUTO` 120조합 중, 상위 3문장·하한 0)

| WEIGHT_RULE_MIN | WEIGHT_ALPHA | LINK_AUTO | 군집 정밀도 | O 유지 | precision | recall |
|---|---|---|---|---|---|---|

| 0 | 0 | 0.60 | 0.613 | 0.936 | 0.556 | 0.833 |
| 0 | 0.5 | 0.55 | 0.624 | 0.916 | 0.565 | 0.833 |

| 0.30 | 0.3 | 0.65 | 0.700 | 0.860 | 0.567 | 0.810 |

- `WEIGHT_MIN`(0 / 0.15 / 0.3)은 α>0 이면 합산 점수가 먼저 걸러 거의 차이가 없다 — 게이트 의미(지역어+재난어만 겹치는 기사 차단)로 0.15 를 둔다.
- 군집 정밀도를 가장 크게 올리는 것은 `WEIGHT_RULE_MIN` — 시설명·기관이 맞아 강한 규칙으로 붙던, 같은 시설의 다른 시기 사건·일반 기획 기사(감천항 병원선 진수식, 다른 해역 어선 전복 등)를 내린다.
- 후속보도 precision 은 설정 사이 차이가 사건 1~3건이다(라벨 90건에서 잡음 수준).

**채택값과 이유**: `WEIGHT_MIN=0.15 · WEIGHT_ALPHA=0.5 · WEIGHT_RULE_MIN=0.25 · LINK_AUTO=0.55(그대로) · FOLLOWUP_TOP_SENTENCES=3 · FOLLOWUP_SENTENCE_MIN=0`.
`WEIGHT_RULE_MIN` 0.3 이 라벨상 조금 낫지만 가상 픽스처의 정상 후속 기사('해맞이터널 붕괴 책임 공무원 2명 기소', overlap 0.28)를 떨어뜨려 픽스처 평가가 깨진다 — 0.25 가 깨지지 않는 최대값. α=0.5 면 기존 `LINK_AUTO=0.55` 를 바꾸지 않고도 α=0.3·LINK_AUTO 0.6 과 같은 효과를 낸다. 관련도 하한(1.4)은 precision 을 0.574 로 조금 올리지만 recall 을 0.738 로 깎아 쓰지 않았다.

**남은 오탐의 원인** (오탐 사건의 양성 기사·발췌를 시뮬레이션 진단으로 하나씩 확인 — 재실행 후 오탐 26건)
- 같은 사건 기사지만 **약속한 조치의 완료·진행이 아닌 것**: 수사 진행(울산화력), 원인 발표의 같은 날 전재(KA-1), '복구작업이 진행 중' 같은 일반 진행 표현 — 규칙은 '무엇이 진행되는지' 를 약속과 대조하지 못한다. LLM live 전환이 가장 먼저 줄일 부분.
- **추출된 약속 자체가 조치가 아님**: '해상에 설치된', '설치된 철제 방화문이 닫혀있었던 것으로 추정된다', '강화도의' — 약속 추출(ⓐ) 규칙의 한계.
- **원천 발언 이전 기사**: 라벨은 원천 기사(대응 발언) 이후만 후속으로 보는데, 시스템은 가장 이른 추적 약속 발언일 이후를 본다(검단·울산화력). 시뮬레이션상 원천 기사 이후로 좁히면 FP 1건만 줄어 이번에는 바꾸지 않았다.
- 상태 '새로운 문제 발생' 이 5→13 건으로 늘었다. 문장 선택으로 '또다시·차질·지연' 이 든 사건 관련 문장이 더 자주 뽑힌다 — 라벨은 사건 단위 후속보도 유무만 있어 이 상태 변화의 옳고 그름은 따로 확인이 필요하다.

**재실행 중 제약**: 연결이 바뀌자 일부 사건의 추출 약속이 달라져 약속 키워드 재검색 질의가 녹화에 없었다(26건, replay_only 실패 — 실 API 호출 금지). 이 사건들은 이전 실행에서 받은 후보를 그대로 쓴다.

- 늦은 같은 유형 새 사고: 창 뒤 제목이 사건 제목과 같은 재난어 + 발생 보도 말(구조·사망·실종·특보 …)이고 돌아보는 말(복구·원인·재판·압수수색 …)이 없으면 검토 큐 이하. 약속 키워드·조치 명사(보강·설치·준설 …)가 있으면 원래 사건의 재발로 남긴다(가상 픽스처 '서리천 제방 또 유실… 보강 구간 바로 옆').
- 지역 필수: 기초 지역 사건은 제목·하이라이트·키워드에 사건 지역어(기초명·사건 제목/핵심어의 지명·동/읍/면/리·'영등포역'→영등포) 또는 시설명(일반어로만 된 '산사태 피해지' 제외). 광역 사건(도·특별시·광역시)은 사건 고유어 하나 이상, 또는 제목에 그 광역(안의 기초) 지명 + 사건 재난어('경기도 폭설 피해 2,930건').
- 다른 지역: 제목에 다른 광역·기초 지명(`regions.PARENT` 로 상위 광역 판정, '예산·강화·진도' 같은 보통명사 겹침 제외)이 있고 사건 지역어·상위 광역·권역(수도권·충청권 …)·시설명이 제목에 없으면 탈락. 사건 고유어가 있고 새 사고 속보가 아니면 남긴다('부산시, 금성호 침몰 사고 피해자 지원').
- 다른 구체 장소: 제목에 사건에 없는 …역·…항·…공장·…센터 등 장소명이 있고 그 장소의 새 사고 속보이며 제목에 사건 고유어가 없으면 검토 큐 이하. 기존 '다른 시드 시설명' 규칙은 그대로.
- 조건은 가중치 핵심 문서 선정에는 쓰지 않는다(조건이 가중치에 기대므로 순환 방지). `LINK_SCOPE_RULES=false` 면 이전 동작.

## 8. 후속 신호 — 약속 추출 엄격화 (2026-10-25, 같은 라벨)

§6 의 남은 오탐을 사건별로 다시 보니 대부분이 **약속이 아닌 문장이 '계획' 으로 추적**된 데서 왔다 — '강화도의', '해상에 설치된', '설치된 철제 방화문이 닫혀있었던 것으로 추정된다', 다른 주제의 인용문('금융지주 회장들 줄소환 예고'). 규칙 어댑터가 구체 행동어(설치·강화·이전·통제 …)가 있고 검토·노력 표현만 없으면 다짐 없이도 '계획' 으로 판정했기 때문이다.

**바꾼 것** (`llm/rules_adapter.py` ⓐ, `pipeline/extract.py`, `experiment/runner.py`)
- 약속 = **다짐이 있는 문장**(하겠다·할 계획·할 예정·방침·키로·하기로·「조성한다」형·문장 끝 '…할 것'). 사실 묘사·추정(것으로 보인다/추정된다)·현재 진행 설명(진행하고 있다)·과거 계획('계획이었다')은 해당없음. 행동 절은 다짐이 걸린 절에서, 어절 경계로 자른다. 구체 행동어에 조성·선포·동원·투입·측정·모니터링·규명·지급·가동·보완·확보·감식·수사·착수·재개를 더했다.
- 원천 기사(대응 발언)의 인용문은 반드시 약속 추출을 받는다 — 인용문 검색 창(발생 +90일) 밖이거나 이번 검색에 다시 안 나오면 규칙 산출물을 지운 뒤 다시 추출되지 않던 문제(`Experiment.ensure_source_promises`).
- 약속이 바뀌면서 달라진 약속 키워드 재검색 질의는 **실 API 로 수집**(record 모드, 이번 작업 누계 약 350회 — 녹화에 저장돼 이후 재생 가능).
