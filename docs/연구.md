# 미결 연구 기록 — 재난 기사 묶기와 후속보도 찾기

> 보도가 없다는 사실은 조치가 없었다는 근거가 아니라, 확인이 필요하다는 신호입니다.

이 문서는 미결이 "사고 뒤 기관이 약속한 조치가 그 뒤 보도됐는가"를 찾는 방법을 어떻게 다듬어 왔는지를 날짜순으로 모은 연구 기록이다.
발표 자료에 그대로 옮길 수 있도록 쉬운 말로 쓰고 숫자는 표로 둔다. 자세한 방법·명령은 `docs/EXPERIMENT.md`, 실행 리포트는 `reports/` 에 있다.
작업하면서 계속 덧붙인다(마지막 갱신 2026-10-25 밤 — 3.7 2단계 적용·사건 라벨 상한까지).

---

## 1. 무엇을 풀고 있나

미결은 두 단계로 일한다.

| 단계 | 하는 일 | 틀리면 생기는 일 |
|---|---|---|
| 1단계 · 기사 묶기(군집) | 사건마다 그 사건을 다룬 기사를 모은다 | 다른 사건 기사가 섞이면 그 기사가 '후속보도' 로 잘못 잡힌다 |
| 2단계 · 후속 신호 | 묶인 기사 중 기관 발언(약속) 뒤에 나온 기사에서 그 조치가 끝났는지·진행 중인지·새 문제가 생겼는지 찾는다 | 일반 복구·점검 기사를 약속의 진행으로 읽거나, 진짜 후속을 놓친다 |

- 대상: 실제 빅카인즈 API 로 모은 재난·안전 사건 **90건**(2023~2025 발생, 산업사고·교통사고·자연재해). 기사 본문 전문은 쓰지 않는다 — API 가 돌려주는 제목·하이라이트 200자·키워드만 쓴다(크롤링 금지).
- LLM 키가 없어 약속 추출·후속 신호 판정은 **규칙 어댑터**(`LLM_MODE=rules`)가 한다.

## 2. 잣대 — 무엇으로 쟀나

### 2.1 라벨 세 가지 (모두 Claude 에이전트가 붙였다 — 사람 라벨이 아니다)

| 라벨 | 파일 | 크기 | 묻는 것 |
|---|---|---|---|
| 사건 라벨 | `backend/gold/experiment_labels.csv` | 90건 (있음 42 · 없음 48) | 원천 발언 뒤 그 약속한 조치의 후속보도가 있는가 + 근거 기사 id |
| 군집 표본 | `backend/gold/cluster_sample.csv` | 434행 | 자동 연결된 기사가 같은 사건 기사인가 |
| 군집 전체 | `backend/gold/cluster_full.csv` | 19,109행 (같은 사건 11,315 · 아님 7,794) | 연결된 기사 전부가 같은 사건인가 + 아니면 사유(무관·예방정책 일반·다른 시기·전국 일반·같은 지역 다른 사고) |

라벨 잡음: 두 에이전트 라벨이 겹치는 395행의 일치도는 0.957(Cohen κ 0.91)이다. 두 라벨러가 서로 독립이라고 보면 라벨 하나의 오류율은 약 2.2% — 이 라벨로 잴 수 있는 정밀도·재현율의 상한은 0.98 언저리이고, 0.01 안팎의 차이는 잡음 안이다. 같은 지침·같은 모델 계열이라 실제 잡음은 이보다 클 수 있다.

사건 라벨은 더 흔들린다. 1차 에이전트가 '있음' 으로 본 49건을 "반박하라" 는 지시를 받은 검증 에이전트가 다시 봐서 7건을 '없음' 으로 뒤집고 6건은 근거 기사를 바꿨다('없음' 41건은 다시 보지 않았다).

| 사건 라벨로 잴 때의 상한 | precision | recall | F1 |
|---|---|---|---|
| 1차 에이전트 라벨을 그대로 따라 하는 시스템 (최종 라벨로 잼) | 0.857 | 1.000 | 0.923 |
| 지금 구조로 찾을 수 있는 최대 — 추적할 약속이 없는 '있음' 3건을 뺌, 오탐 0 가정 | 1.000 | 0.929 | 0.963 |

에이전트끼리도 이만큼 어긋나므로, 이 라벨로 잴 수 있는 후속보도 F1 의 실질 상한은 0.92 언저리로 본다. 지금 판정 근처에서는 사건 1건이 F1 을 0.007(오탐 1건)~0.014(놓친 것 1건) 움직인다.

### 2.2 지표

| 지표 | 뜻 |
|---|---|
| 군집 정밀도 | 자동 연결된 기사 중 같은 사건 기사의 비율 |
| 군집 재현율 | 같은 사건 기사 중 자동 연결로 남은 비율 (검토 대기·탈락은 빠진 것으로 센다) |
| 후속보도 precision | 시스템이 '후속보도 있음' 이라 한 사건 중 라벨도 '있음' 인 비율 |
| 후속보도 recall | 라벨이 '있음' 인 사건 중 시스템도 '있음' 이라 한 비율 |
| F1 | precision 과 recall 의 조화평균 |
| 근거까지 맞은 탐지 | 시스템이 '있음' 의 근거로 든 기사가 같은 사건 기사(군집 라벨 O)인 사건 수 — 운으로 맞힌 것을 가려낸다 |

### 2.3 교차검증

학습하는 방법은 **사건 단위 5-fold 교차검증**으로 잰다. 사건 90건을 다섯 묶음으로 나누고, 한 묶음의 사건은 학습에서 빼고 평가에만 쓴다. 같은 사건의 기사가 학습과 평가에 함께 들어가지 않으므로 '처음 보는 사건' 에서의 성능에 가깝다. 규칙은 사람이(여기서는 에이전트가) 90건 전체를 보며 만들었기 때문에, 규칙의 수치는 조금 낙관적일 수 있다.

## 3. 연대기

### 3.1 10-22 · 첫 실험 — 실 API, 자동 시드 150건

| 단계 | 결과 |
|---|---|
| 원천 기사(기관 대응 발언이 인용된 재난 기사) | 1,559건 수집 → 같은 사건끼리 묶어 1,017 그룹 → 추적 사건 150건 |
| 후속보도 있음(규칙 판정) | 87 / 150 (58%) |
| 실 API 호출 | 녹화 파일 6,678개 (최종 실행 요청 5,406) |

이때는 라벨이 없었다. 근거 문장 30개를 훑어보니 절반가량은 실제 후속보도였고, 나머지는 다른 사건 기사가 섞였거나 규칙이 문장을 잘못 읽은 경우였다.

### 3.2 10-23 · 시드 정리와 에이전트 라벨

자동 시드 150건을 에이전트가 다듬어 90건으로 줄였다.

| 뺀 이유 | 건수 |
|---|---|
| 예방·정책·계절 대비 기사(특정 사고 없음) | 28 |
| 중복 사건 | 16 |
| 집계형·비사건 | 10 |
| 범죄·형사·정치 | 5 |
| 해외 사건 | 1 |

90건으로 다시 돌리고(실 API 약 3,100회 추가) 에이전트 16개가 라벨을 붙였다.

| 지표 | 값 |
|---|---|
| 라벨 '후속보도 있음' | 42 / 90 (47%) |
| 시스템 '있음' | 62 |
| 후속보도 precision / recall | 0.53 / 0.79 |
| 군집 정밀도 (표본) | 0.58 |

규칙 판정의 절반 가까이가 과대 판정이었고, 원인은 대부분 기사 묶음에 섞인 다른 사건 기사였다.

### 3.3 10-24 · 사건별 단어 가중치와 문장 관련도

- 사건마다 '그 사건에만 나오는 말' 에 높은 가중치를 주는 TF-IDF 식 단어 가중치를 만들고, 지역어+재난어만 겹치는 기사를 게이트에서 거르게 했다.
- 후속 신호는 약속과 가장 관련 있는 문장 3개 안에서만 완료·진행 표현을 보게 했다.

| 지표 | 전 | 후 |
|---|---|---|
| 군집 정밀도 (표본) | 0.568 | 0.652 |
| 후속보도 precision / recall | 0.532 / 0.786 | 0.567 / 0.810 |
| 후속보도 F1 | 0.635 | 0.667 |

해 보고 버린 것: 문장 관련도 하한(precision 0.574 로 조금 오르지만 recall 0.738 로 떨어짐), 강한 규칙 가중치 하한 0.3(가상 정답셋의 정상 기사를 떨어뜨림).

### 3.4 10-25 · 약속 추출 엄격화 — '다짐 문장' 만 약속으로

'해상에 설치된', '…것으로 추정된다' 같은 서술 조각이 약속으로 잡히던 문제를, 하겠다·할 계획·할 예정·키로 같은 다짐 표현이 있는 문장만 약속으로 보게 고쳤다.

| 지표 | 전 | 후 (DB 사본) |
|---|---|---|
| 추적 약속 수 | 1,190 | 819 |
| 후속보도 precision / recall | 0.567 / 0.810 | 0.614 / 0.833 |

해 보고 버린 것: 원천 발언의 약속만 추적(recall 0.40~0.71 로 급락), 원천 발언일 이후 기사만(같은 이유), 완료 표현 바로 옆에 약속 대상어 요구(recall 만 하락), 신뢰도 하한 상향(precision 이 더 오르지 않음). 달라진 약속의 재검색에 실 API 약 350회.

### 3.5 10-25 · 기간 창·지역 필수 조건·일반 시설어·새문제 표현

- 발생 90일 뒤 기사는 제목에 사건 고유어가 있어야 붙인다(몇 년 뒤 후속은 막지 않는다 — 만덕~센텀 2026 개통·지반 침하).
- 기초 지역 사건은 지역어가 있어야 하고, 제목에 다른 지역만 있으면 뺀다. 늦은 같은 유형의 새 사고 속보는 검토 대기로.
- '물류센터·창고·시장' 같은 일반 시설어는 시설 일치로 보지 않는다. '새로운 문제' 표현을 좁혔다(배경 서술·조건·부정·예방 촉구 제외).

| 지표 | 전 | 후 |
|---|---|---|
| 군집 정밀도 (표본) | 0.652 | 0.744 |
| 군집 정밀도 / 재현율 (전체 라벨) | 0.671 / 0.803 | 0.766 / 0.782 |
| 후속보도 precision / recall | 0.567 / 0.810 | 0.630 / 0.810 |
| 후속보도 F1 | 0.667 | 0.709 |
| 상태 (완료 / 진행 / 새문제 / 부족 / 불가) | 30 / 15 / 13 / 28 / 4 | 26 / 17 / 7 / 36 / 4 |

규칙별로 뺀 기사 (바꾸기 전 자동 연결 중):

| 규칙 | 뺀 다른 사건 기사 | 함께 빠진 같은 사건 기사 |
|---|---|---|
| 창 뒤 고유어 없음 | 870 | 94 |
| 기초 지역어 없음 | 342 | 8 |
| 제목에 다른 지역 | 249 | 30 |
| 늦은 같은 유형 새 사고 → 검토 | 82 | 27 |
| 광역 사건 고유어 없음 | 55 | 9 |

해 보고 버린 것: '다른 구체 장소' 를 넓게 걸기(다른 사건 32건 빼려다 같은 사건 80건을 뺌), 검토 대기 기사 승격(O 비율 0.17~0.53 이라 자동 연결보다 정밀도가 낮음), 창 365일(정밀도 0.73), 제목만 보는 늦은 기사 판정(회귀 사례 손실). 녹화 없던 약속 재검색 14회는 실 API 로 채웠다.

### 3.6 10-25 · 학습 기반 재순위 (docs/EXPERIMENT.md §9)

**진단** — 그래도 자동 연결의 약 23%(라벨 행 11,545 중 2,699)가 다른 사건 기사였다.

| 남은 오염의 사유 | 자동 연결에 남은 수 |
|---|---|
| 무관 | 1,092 |
| 예방·정책 일반 | 692 |
| 전국 재난 일반 | 356 |
| 다른 시기 같은 유형 | 302 |
| 같은 지역 다른 사고 | 235 |

- 60%가 '시설명·기관이 맞으면 자동 연결' 하는 강한 규칙 경로로 붙었다.
- 검토 대기에 갇힌 같은 사건 기사 2,119건 중 1,467건은 다른 사건의 시설명이 '산사태·집중호우·어선' 같은 일반어라서 걸렸다.

**세 가지 방법 비교** (사건 단위 5-fold)

| 방법 | 정밀도 | 재현율 | F1 |
|---|---|---|---|
| 지금 규칙 | 0.765 | 0.783 | 0.774 |
| A. 규칙 두 개 추가 | 0.794 | 0.865 | 0.828 |
| B. 피처 분류기 (숫자 특징 53개 + 제목 단어) | 0.873 | 0.881 | 0.877 |
| C. 교차 인코더 (사건 설명과 기사 제목을 함께 읽는 모델) | 0.899 | 0.885 | 0.892 |
| **B 와 C 의 평균** | **0.900** | **0.900** | **0.900** |

(모두 '바닥 규칙' 포함 — 발생 90일 뒤 자동 연결이면서 제목에 사건 시설명이 있는 기사는 내리지 않는다. 학습 모델이 만덕~센텀 2026 후속을 다른 사고로 보기 때문이다.)

**실험 DB 에 적용해 보니**

| 지표 | 끔 | 켬 |
|---|---|---|
| 군집 정밀도 / 재현율 (전체 라벨) | 0.766 / 0.782 | 0.901 / 0.897 |
| 검토 대기 | 4,437 | 1,843 |
| 후속보도 precision / recall / F1 | 0.630 / 0.810 / 0.709 | 0.554 / 0.738 / 0.633 |
| 근거까지 맞은 탐지 | 26 | 28 |
| 다른 사건 기사로 맞힌 탐지 | 8 | 3 |

기사 묶음은 깨끗해졌지만 후속보도 점수는 떨어졌다. 이유는 두 가지였다. 첫째, 지금 맞히던 34건 중 8건은 다른 사건 기사를 근거로 '운으로' 맞힌 것이라 묶음이 깨끗해지자 사라졌다. 둘째, 새로 들어온 같은 사건의 일반 복구·점검 기사를 규칙 어댑터가 '약속의 진행' 으로 읽었다. 미리 정한 기준(후속보도 F1 이 0.02 넘게 떨어지면 되돌림)에 따라 이때는 끈 채로 두었다.

**사용자 결정 (10-25 저녁)**: 재순위를 켜고, 떨어진 후속보도 점수는 2단계(후속 신호 판정)에서 되찾는다. 녹화에 없는 질의는 실 API 로 받아도 된다.

- 회귀 사례는 그대로다: 만덕~센텀 2026 자동 연결 19건(상태 '새로운 문제 발생' 유지 — '또 지반 침하'), 영도구 방호울타리 3건(완료), 현대시장 복구 7건(완료).
- 시연 사건 중 상태가 바뀐 것: 인천대교 새로운 문제 → 완료, 군위 제방 후속보도 부족 → 진행(라벨은 '없음' — 남은 오탐), 5호선 방화 진행 → 후속보도 부족(라벨은 '있음' — 다음 날 순찰·점검 기사는 상태 표현이 없어 놓침).
- 공공기관 게시판 확인('후속보도 부족·판단 불가' 로 90일 넘게 조용한 사건만)은 다시 돌리지 않았다. 마지막 확인 때 조건에 든 사건은 19건이었고, 바뀐 상태로는 31건이 조건에 든다. 기관 발표 확인 4건(통복터널·5호선·군위 제방·대덕구 호우)은 그대로 붙어 있다 — 군위는 이제 '진행' 이라 조건 밖이지만 저장된 발표는 보조 근거로 남는다.

## 6. 한계

- **에이전트 라벨**: 모든 라벨은 Claude 에이전트가 붙였다. 사람이 다시 보면 수치가 달라질 수 있다. 학습 모델은 에이전트 지침의 경계를 배운다.
- **선택 편향**: 원천 기사는 인용문 검색 상위 표본(108구간 × 200건)에서 골랐고, 질의 건수 400건 안으로 좁혀지는 사건 쪽으로 기울었다(전국 단위 대형 재난보다 시설·지역이 특정되는 사건). 90건은 모집단 전수가 아니다.
- **녹화 재생**: 연결이 바뀌면 약속이 달라지고 새 재검색 질의가 생긴다. 실 API 를 쓰지 않은 단계에서는 녹화에 없는 질의를 건너뛰고 이전 후보로 진행했다.
- **기사 텍스트 범위**: 제목·하이라이트 200자·키워드만 본다. 본문 깊숙이 있는 후속 내용은 보지 못한다.
- **규칙 어댑터**: LLM 이 아니라 표현과 단어 겹침으로 판정한다. 같은 사건의 다른 조치나 일반 복구 기사를 약속의 진행과 구별하기 어렵다.
- **사건 수**: 사건 라벨이 90건이라 후속보도 지표에서 1~2건 차이는 잡음 수준이다.

## 7. 남은 과제

- **사람 라벨로 다시 재기** — 최소한 사건 라벨 90건. 지금 수치는 모두 에이전트 라벨 기준이고(사건 라벨의 실질 상한 F1 0.92 언저리, 2.1), 2단계에서는 1~2건 차이가 F1 0.007~0.03 을 움직인다.
- **후속 신호를 문장 의미로 판정하기** — 남은 틀린 '있음' 의 대부분은 '같은 사건의 응급 대응·다른 조치' 를 '약속한 조치의 진행' 으로 읽은 경우다. 규칙과 작은 분류기로는 더 가르지 못했다. LLM 키가 생기면 약속 추출·후속 신호를 LLM 으로 바꾸고 같은 잣대(사건 90건 · 근거까지 맞은 탐지)로 비교한다.
- **약속이 없는 사건** — 원천 발언이 요구·설명이라 추적할 약속이 없는 사건 14건(라벨 '있음' 3건: 의성 산불·융건릉·국정자원)은 지금 방식으로 찾을 수 없다.
- **검토 대기·미연결 근거** — 라벨 근거 기사가 검토 대기이거나 수집되지 않은 사건 3건(예천·봉화, 공주, 구로역)은 1단계 수집·연결 몫이다.
- **공공기관 게시판 확인 다시 돌리기** — 상태가 바뀌어 조건에 드는 사건이 19건 → 31건이 됐다. 네트워크가 필요한 별도 기능이라(공공기관 공식 게시판, robots.txt·2초 간격) 이번에는 돌리지 않았다. 발표 전에 `run_notices.py --all` 로 다시 맞춘다.
- **다음 날 응급 대응 보도** — 기준일을 원천 발언 다음 날로 당기며 되찾은 후속(철거 완료·안전진단 추진)과 함께, 수색·감식·압수수색 같은 다음 날 보도가 틀린 '있음' 의 새 원천이 됐다.
