# 미결 연구 기록 — 재난 기사 묶기와 후속보도 찾기

> 보도가 없다는 사실은 조치가 없었다는 근거가 아니라, 확인이 필요하다는 신호입니다.

이 문서는 미결이 "사고 뒤 기관이 약속한 조치가 그 뒤 보도됐는가"를 찾는 방법을 어떻게 다듬어 왔는지를 날짜순으로 모은 연구 기록이다.
발표 자료에 그대로 옮길 수 있도록 쉬운 말로 쓰고 숫자는 표로 둔다. 자세한 방법·명령은 `docs/EXPERIMENT.md`, 실행 리포트는 `reports/` 에 있다.
작업하면서 계속 덧붙인다(마지막 갱신 2026-10-26 — 3.8 목표 F1 0.80 시도와 병목까지).

---

## 1. 무엇을 풀고 있나

미결은 두 단계로 일한다.

| 단계 | 하는 일 | 틀리면 생기는 일 |
|---|---|---|
| 1단계 · 기사 묶기(군집) | 사건마다 그 사건을 다룬 기사를 모은다 | 다른 사건 기사가 섞이면 그 기사가 '후속보도' 로 잘못 잡힌다 |
| 2단계 · 후속 신호 | 묶인 기사 중 기관 발언(약속) 뒤에 나온 기사에서 그 조치가 끝났는지·진행 중인지·새 문제가 생겼는지 찾는다 | 일반 복구·점검 기사를 약속의 진행으로 읽거나, 진짜 후속을 놓친다 |

- 대상: 실제 빅카인즈 API 로 모은 재난·안전 사건 **90건**(2023~2025 발생, 산업사고·교통사고·자연재해). 기사 본문 전문은 쓰지 않는다 — API 가 돌려주는 제목·하이라이트 200자·키워드만 쓴다(크롤링 금지).
- LLM 키가 없어 약속 추출·후속 신호 판정은 **규칙 어댑터**(`LLM_MODE=rules`)가 한다.

## 2. 잣대 — 무엇으로 쟀나

### 2.1 라벨 세 가지 (모두 Claude 에이전트가 붙였다 — 사람 라벨이 아니다)

| 라벨 | 파일 | 크기 | 묻는 것 |
|---|---|---|---|
| 사건 라벨 | `backend/gold/experiment_labels.csv` | 90건 (있음 42 · 없음 48) | 원천 발언 뒤 그 약속한 조치의 후속보도가 있는가 + 근거 기사 id |
| 군집 표본 | `backend/gold/cluster_sample.csv` | 434행 | 자동 연결된 기사가 같은 사건 기사인가 |
| 군집 전체 | `backend/gold/cluster_full.csv` | 19,109행 (같은 사건 11,315 · 아님 7,794) | 연결된 기사 전부가 같은 사건인가 + 아니면 사유(무관·예방정책 일반·다른 시기·전국 일반·같은 지역 다른 사고) |

라벨 잡음: 두 에이전트 라벨이 겹치는 395행의 일치도는 0.957(Cohen κ 0.91)이다. 두 라벨러가 서로 독립이라고 보면 라벨 하나의 오류율은 약 2.2% — 이 라벨로 잴 수 있는 정밀도·재현율의 상한은 0.98 언저리이고, 0.01 안팎의 차이는 잡음 안이다. 같은 지침·같은 모델 계열이라 실제 잡음은 이보다 클 수 있다.

사건 라벨은 더 흔들린다. 1차 에이전트가 '있음' 으로 본 49건을 "반박하라" 는 지시를 받은 검증 에이전트가 다시 봐서 7건을 '없음' 으로 뒤집고 6건은 근거 기사를 바꿨다('없음' 41건은 다시 보지 않았다).

| 사건 라벨로 잴 때의 상한 | precision | recall | F1 |
|---|---|---|---|
| 1차 에이전트 라벨을 그대로 따라 하는 시스템 (최종 라벨로 잼) | 0.857 | 1.000 | 0.923 |
| 지금 구조로 찾을 수 있는 최대 — 추적할 약속이 없는 '있음' 3건을 뺌, 오탐 0 가정 | 1.000 | 0.929 | 0.963 |

에이전트끼리도 이만큼 어긋나므로, 이 라벨로 잴 수 있는 후속보도 F1 의 실질 상한은 0.92 언저리로 본다. 지금 판정 근처에서는 사건 1건이 F1 을 0.007(오탐 1건)~0.014(놓친 것 1건) 움직인다.

### 2.2 지표

| 지표 | 뜻 |
|---|---|
| 군집 정밀도 | 자동 연결된 기사 중 같은 사건 기사의 비율 |
| 군집 재현율 | 같은 사건 기사 중 자동 연결로 남은 비율 (검토 대기·탈락은 빠진 것으로 센다) |
| 후속보도 precision | 시스템이 '후속보도 있음' 이라 한 사건 중 라벨도 '있음' 인 비율 |
| 후속보도 recall | 라벨이 '있음' 인 사건 중 시스템도 '있음' 이라 한 비율 |
| F1 | precision 과 recall 의 조화평균 |
| 근거까지 맞은 탐지 | 시스템이 '있음' 의 근거로 든 기사가 같은 사건 기사(군집 라벨 O)인 사건 수 — 운으로 맞힌 것을 가려낸다 |

### 2.3 교차검증

학습하는 방법은 **사건 단위 5-fold 교차검증**으로 잰다. 사건 90건을 다섯 묶음으로 나누고, 한 묶음의 사건은 학습에서 빼고 평가에만 쓴다. 같은 사건의 기사가 학습과 평가에 함께 들어가지 않으므로 '처음 보는 사건' 에서의 성능에 가깝다. 규칙은 사람이(여기서는 에이전트가) 90건 전체를 보며 만들었기 때문에, 규칙의 수치는 조금 낙관적일 수 있다.

## 3. 연대기

### 3.1 10-22 · 첫 실험 — 실 API, 자동 시드 150건

| 단계 | 결과 |
|---|---|
| 원천 기사(기관 대응 발언이 인용된 재난 기사) | 1,559건 수집 → 같은 사건끼리 묶어 1,017 그룹 → 추적 사건 150건 |
| 후속보도 있음(규칙 판정) | 87 / 150 (58%) |
| 실 API 호출 | 녹화 파일 6,678개 (최종 실행 요청 5,406) |

이때는 라벨이 없었다. 근거 문장 30개를 훑어보니 절반가량은 실제 후속보도였고, 나머지는 다른 사건 기사가 섞였거나 규칙이 문장을 잘못 읽은 경우였다.

### 3.2 10-23 · 시드 정리와 에이전트 라벨

자동 시드 150건을 에이전트가 다듬어 90건으로 줄였다.

| 뺀 이유 | 건수 |
|---|---|
| 예방·정책·계절 대비 기사(특정 사고 없음) | 28 |
| 중복 사건 | 16 |
| 집계형·비사건 | 10 |
| 범죄·형사·정치 | 5 |
| 해외 사건 | 1 |

90건으로 다시 돌리고(실 API 약 3,100회 추가) 에이전트 16개가 라벨을 붙였다.

| 지표 | 값 |
|---|---|
| 라벨 '후속보도 있음' | 42 / 90 (47%) |
| 시스템 '있음' | 62 |
| 후속보도 precision / recall | 0.53 / 0.79 |
| 군집 정밀도 (표본) | 0.58 |

규칙 판정의 절반 가까이가 과대 판정이었고, 원인은 대부분 기사 묶음에 섞인 다른 사건 기사였다.

### 3.3 10-24 · 사건별 단어 가중치와 문장 관련도

- 사건마다 '그 사건에만 나오는 말' 에 높은 가중치를 주는 TF-IDF 식 단어 가중치를 만들고, 지역어+재난어만 겹치는 기사를 게이트에서 거르게 했다.
- 후속 신호는 약속과 가장 관련 있는 문장 3개 안에서만 완료·진행 표현을 보게 했다.

| 지표 | 전 | 후 |
|---|---|---|
| 군집 정밀도 (표본) | 0.568 | 0.652 |
| 후속보도 precision / recall | 0.532 / 0.786 | 0.567 / 0.810 |
| 후속보도 F1 | 0.635 | 0.667 |

해 보고 버린 것: 문장 관련도 하한(precision 0.574 로 조금 오르지만 recall 0.738 로 떨어짐), 강한 규칙 가중치 하한 0.3(가상 정답셋의 정상 기사를 떨어뜨림).

### 3.4 10-25 · 약속 추출 엄격화 — '다짐 문장' 만 약속으로

'해상에 설치된', '…것으로 추정된다' 같은 서술 조각이 약속으로 잡히던 문제를, 하겠다·할 계획·할 예정·키로 같은 다짐 표현이 있는 문장만 약속으로 보게 고쳤다.

| 지표 | 전 | 후 (DB 사본) |
|---|---|---|
| 추적 약속 수 | 1,190 | 819 |
| 후속보도 precision / recall | 0.567 / 0.810 | 0.614 / 0.833 |

해 보고 버린 것: 원천 발언의 약속만 추적(recall 0.40~0.71 로 급락), 원천 발언일 이후 기사만(같은 이유), 완료 표현 바로 옆에 약속 대상어 요구(recall 만 하락), 신뢰도 하한 상향(precision 이 더 오르지 않음). 달라진 약속의 재검색에 실 API 약 350회.

### 3.5 10-25 · 기간 창·지역 필수 조건·일반 시설어·새문제 표현

- 발생 90일 뒤 기사는 제목에 사건 고유어가 있어야 붙인다(몇 년 뒤 후속은 막지 않는다 — 만덕~센텀 2026 개통·지반 침하).
- 기초 지역 사건은 지역어가 있어야 하고, 제목에 다른 지역만 있으면 뺀다. 늦은 같은 유형의 새 사고 속보는 검토 대기로.
- '물류센터·창고·시장' 같은 일반 시설어는 시설 일치로 보지 않는다. '새로운 문제' 표현을 좁혔다(배경 서술·조건·부정·예방 촉구 제외).

| 지표 | 전 | 후 |
|---|---|---|
| 군집 정밀도 (표본) | 0.652 | 0.744 |
| 군집 정밀도 / 재현율 (전체 라벨) | 0.671 / 0.803 | 0.766 / 0.782 |
| 후속보도 precision / recall | 0.567 / 0.810 | 0.630 / 0.810 |
| 후속보도 F1 | 0.667 | 0.709 |
| 상태 (완료 / 진행 / 새문제 / 부족 / 불가) | 30 / 15 / 13 / 28 / 4 | 26 / 17 / 7 / 36 / 4 |

규칙별로 뺀 기사 (바꾸기 전 자동 연결 중):

| 규칙 | 뺀 다른 사건 기사 | 함께 빠진 같은 사건 기사 |
|---|---|---|
| 창 뒤 고유어 없음 | 870 | 94 |
| 기초 지역어 없음 | 342 | 8 |
| 제목에 다른 지역 | 249 | 30 |
| 늦은 같은 유형 새 사고 → 검토 | 82 | 27 |
| 광역 사건 고유어 없음 | 55 | 9 |

해 보고 버린 것: '다른 구체 장소' 를 넓게 걸기(다른 사건 32건 빼려다 같은 사건 80건을 뺌), 검토 대기 기사 승격(O 비율 0.17~0.53 이라 자동 연결보다 정밀도가 낮음), 창 365일(정밀도 0.73), 제목만 보는 늦은 기사 판정(회귀 사례 손실). 녹화 없던 약속 재검색 14회는 실 API 로 채웠다.

### 3.6 10-25 · 학습 기반 재순위 (docs/EXPERIMENT.md §9)

**진단** — 그래도 자동 연결의 약 23%(라벨 행 11,545 중 2,699)가 다른 사건 기사였다.

| 남은 오염의 사유 | 자동 연결에 남은 수 |
|---|---|
| 무관 | 1,092 |
| 예방·정책 일반 | 692 |
| 전국 재난 일반 | 356 |
| 다른 시기 같은 유형 | 302 |
| 같은 지역 다른 사고 | 235 |

- 60%가 '시설명·기관이 맞으면 자동 연결' 하는 강한 규칙 경로로 붙었다.
- 검토 대기에 갇힌 같은 사건 기사 2,119건 중 1,467건은 다른 사건의 시설명이 '산사태·집중호우·어선' 같은 일반어라서 걸렸다.

**세 가지 방법 비교** (사건 단위 5-fold)

| 방법 | 정밀도 | 재현율 | F1 |
|---|---|---|---|
| 지금 규칙 | 0.765 | 0.783 | 0.774 |
| A. 규칙 두 개 추가 | 0.794 | 0.865 | 0.828 |

| C. 교차 인코더 (사건 설명과 기사 제목을 함께 읽는 모델) | 0.899 | 0.885 | 0.892 |
| **B 와 C 의 평균** | **0.900** | **0.900** | **0.900** |

(모두 '바닥 규칙' 포함 — 발생 90일 뒤 자동 연결이면서 제목에 사건 시설명이 있는 기사는 내리지 않는다. 학습 모델이 만덕~센텀 2026 후속을 다른 사고로 보기 때문이다.)

**실험 DB 에 적용해 보니**

| 지표 | 끔 | 켬 |
|---|---|---|

기사 묶음은 깨끗해졌지만 후속보도 점수는 떨어졌다. 이유는 두 가지였다. 첫째, 지금 맞히던 34건 중 8건은 다른 사건 기사를 근거로 '운으로' 맞힌 것이라 묶음이 깨끗해지자 사라졌다. 둘째, 새로 들어온 같은 사건의 일반 복구·점검 기사를 규칙 어댑터가 '약속의 진행' 으로 읽었다. 미리 정한 기준(후속보도 F1 이 0.02 넘게 떨어지면 되돌림)에 따라 이때는 끈 채로 두었다.

**사용자 결정 (10-25 저녁)**: 재순위를 켜고, 떨어진 후속보도 점수는 2단계(후속 신호 판정)에서 되찾는다. 녹화에 없는 질의는 실 API 로 받아도 된다.

- 회귀 사례는 그대로다: 만덕~센텀 2026 자동 연결 19건(상태 '새로운 문제 발생' 유지 — '또 지반 침하'), 영도구 방호울타리 3건(완료), 현대시장 복구 7건(완료).
- 시연 사건 중 상태가 바뀐 것: 인천대교 새로운 문제 → 완료, 군위 제방 후속보도 부족 → 진행(라벨은 '없음' — 남은 오탐), 5호선 방화 진행 → 후속보도 부족(라벨은 '있음' — 다음 날 순찰·점검 기사는 상태 표현이 없어 놓침).
- 공공기관 게시판 확인('후속보도 부족·판단 불가' 로 90일 넘게 조용한 사건만)은 다시 돌리지 않았다. 마지막 확인 때 조건에 든 사건은 19건이었고, 바뀐 상태로는 31건이 조건에 든다. 기관 발표 확인 4건(통복터널·5호선·군위 제방·대덕구 호우)은 그대로 붙어 있다 — 군위는 이제 '진행' 이라 조건 밖이지만 저장된 발표는 보조 근거로 남는다.

### 3.8 10-26 · 목표를 올림 — 후속보도 F1 0.80 (닿지 못함, 최고 0.709 ± 0.018 — 라벨의 측정 상한)

사용자 지시(10-25 자정 무렵): 후속보도 탐지 **F1 0.80 이상**. 잣대는 그대로 — 사건 라벨 90건의 precision·recall·F1, 군집 정밀도 0.90 유지, 회귀 사례(만덕·영도구·현대시장) 유지.

- 규칙 보강으로 안 되면 학습 판정(약속 문장–기사 문장 쌍 분류기, 교차 인코더 포함)까지 간다.
- 사건 라벨 90건만으로 학습 자료가 모자라면 군집 라벨·라벨 근거 기사 id·검증자 메모로 **기사(문장) 단위 정답을 더 만든다** — 이것도 에이전트 라벨이다. 평가용이 아니라 학습용이고, 평가는 언제나 사건 라벨 90건(사건 단위 교차검증)이다.
- 숫자를 맞추려고 라벨이나 잣대를 바꾸지 않는다. 0.80 에 못 미치면 어디까지 갔고 무엇이 병목인지 수치로 남긴다.
- 설계 갈림길에서는 자문 세션(「미결 연구 자문」)에 묻고, 질문과 답의 요지를 여기에 적는다.

출발점: 3.7 ⑦ 의 실험 DB — '있음' 53 · TP 33 · FP 20 · FN 9 · precision 0.623 · recall 0.786 · **F1 0.695**. 0.80 이 되려면 예를 들어 TP 36 · FP 12(precision 0.75 · recall 0.86) 또는 TP 34 · FP 9 가 필요하다.

| 원천 발언 유형 | 라벨 있음 (시스템 있음) | 라벨 없음 (시스템 있음) |

**② 자문** — 위 수치와 함께 "기사 단위 정답을 근거 기사=1 · '없음' 사건 후보=0 · '있음' 사건의 나머지=제외로 두고 (원천 발언, 기사) 교차 인코더 + 피처 모델 → 사건 최댓값으로 갈지, 에이전트 라벨로 양성을 먼저 늘릴지" 를 자문 세션에 물었다(답을 기다리며 후보·피처 추출을 진행). 맹검 판정 결과(⑤)가 나온 뒤 "독립 판정과 라벨의 일치가 κ 0.3 남짓인데 0.80 을 계속 노릴지, 병목 보고로 마무리할지" 를 한 번 더 물었다. 두 답은 ⑧ 을 쓴 뒤에 왔다 — 요지와 검증은 ⑨.

**③ 기사 단위 학습 판정 (피처만)** — `backend/scripts/train_followup_pairs.py`

지금 DB 에서 사건 90건의 후보 기사를 다시 뽑아(연결 14,172건, 그중 판정 범위 — 활성·확률 바닥 통과·원천 발언 다음 날부터 — 4,961건) 지금 판정을 그대로 재현하는 것부터 확인했다('있음' 53 · TP 33 · FP 20). 판정 범위 후보의 정답: 1 = 89건(근거 기사와 전재), 0 = 1,926건('없음' 사건의 후보), 모름 = 2,946건('있음' 사건의 나머지).

후보마다 피처 70여 개(규칙 판정 — 사건의 모든 약속 · 원천 발언 전체를 약속으로 본 것 · 원천 발언의 다짐 절, 원천 발언 유형, 날짜, 연결 확률, 원천 발언·약속과의 임베딩 유사도, 제목의 완료·진행·계획·응급·사설 표현, 기사 속 인용문의 발언 기관)를 만들고, 기사 확률의 사건 최댓값으로 '있음' 을 정했다(문턱은 안쪽 교차검증).

| 방법 | F1 (기본 나누기) | precision | recall | 나누기 6가지 평균 |
|---|---|---|---|---|
| 지금 규칙 | 0.695 | 0.623 | 0.786 | – |
| 로지스틱 회귀 | 0.686 | 0.571 | 0.857 | 0.664 ± 0.033 |
| 그래디언트 부스팅 | 0.699 | 0.590 | 0.857 | 0.655 ± 0.026 |

recall 은 오르지만 precision 이 떨어진다. 분리력을 따로 재 보니 기사 단위 AUC 는 0.83~0.87 인데 **사건 최댓값의 AUC 는 0.72~0.75** 이고, 정답을 보고 문턱을 골라도 F1 은 0.747 까지다. '없음' 사건마다 후보 수십 건 중 하나만 높아도 '있음' 이 되기 때문이다.

'없음' 사건에서 점수가 가장 높은 기사를 보면 원천 발언의 조치를 전하는 것처럼 읽히는 기사가 적지 않다(예: 산청·가평 '산청군, 극한호우 피해 복구에 6362억원 투입', 충남 집중호우 '수해 복구 사업 우기 전 마무리 박차', 군위 '추석 전 재난지원금 선지급'). 이런 사건의 라벨 메모에는 "연결 표본은 발생 직후 기사뿐" 이라는 말이 자주 나온다 — 라벨러가 본 표본(사건당 약 40건) 밖의 기사일 수 있다. 이것이 학습으로도 넘기 어려운 벽인지 재기 위해, 사건 라벨·메모를 보여 주지 않은 채 에이전트 6개가 사건마다 후보 최대 16건(규칙 양성 ∪ 피처 모델 상위 8 ∪ 원천 발언 유사도 상위 4 ∪ 근거·전재, 모두 855건)을 판정하게 했다 — 엄격(원천 발언의 그 조치) · 넓게(그 사건에 대한 기관 대응) 두 질문. 이 판정은 학습용 기사 정답으로도 쓴다(에이전트 라벨).

**④ 교차 인코더 첫 시도 — 지름길에 빠짐** — `backend/scripts/train_followup_cross.py`

(원천 발언, 기사 제목+하이라이트) 쌍을 ko-sroberta 교차 인코더로 학습했다. 처음에는 '있음' 사건의 정답 모름 후보를 학습에서 뺐는데, 그러면 학습 자료에서 '있음' 사건의 기사는 모두 1, '없음' 사건의 기사는 모두 0 이 된다. 모델은 기사를 읽지 않고 **원천 발언만 보고 사건을 외웠다** — 학습 손실은 0.012 까지 내려갔지만 처음 보는 사건(평가 fold)의 기사 AUC 는 0.50(동전 던지기)이었다. 같은 원천 발언 안에서 "후속인 기사" 와 "아닌 기사" 를 함께 보여 줘야 한다. 그래서 '있음' 사건의 나머지 후보를 0 으로 두고(대부분은 사고 속보·피해 집계라 후속이 아니다) 다시 학습하고, 에이전트 판정이 오면 그 0/1 을 에이전트 판정으로 바꾼다.

| 교차 인코더 (원천 발언, 기사) — 바깥 5-fold 평가 점수 | 기사 AUC (근거 대 '없음' 사건) | 기사 AUC ('있음' 사건 안) | 사건 최댓값 AUC | 문턱 최적 F1 (낙관) |
|---|---|---|---|---|
| '있음' 사건의 나머지를 뺌 (지름길) | 0.50 (fold 0) | – | – | – |
| '있음' 사건의 나머지 = 0 | 0.636 | 0.640 | 0.660 | 0.677 |
| 에이전트 엄격 판정으로 정답 보강 (양성 217) — ⑥ 뒤에 돌림 | 0.741 | 0.686 | 0.626 | 0.680 |
| (참고) 피처 그래디언트 부스팅 | 0.72~0.87 | – | 0.715~0.746 | 0.717~0.747 |

fold 마다 기사 AUC 가 0.51~0.82 로 크게 흔들렸다. 양성 76건 남짓으로는 교차 인코더가 "원천 발언의 조치 ↔ 기사의 조치 상태" 관계를 일반화하지 못한다 — 피처 모델보다도 낮다.

**⑤ 맹검 에이전트 판정 — 라벨과 독립 판정은 얼마나 맞나**

에이전트 6개가 사건 라벨·메모를 보지 않고 사건 90건의 후보 855건을 두 질문으로 판정했다(엄격 = 원천 발언의 그 조치가 발언 뒤 진행·완료·차질을 빚었나, 넓게 = 그 사건에 대한 기관 대응이 진행·완료·차질을 빚었나). 결과는 `backend/data/experiment/followup_agent_labels.csv`(에이전트 라벨, 학습용).

- 라벨러가 근거로 든 기사(전재 포함 89건)를 에이전트는 엄격 기준으로 38건(43%)만, 넓은 기준으로 75건(84%) 후속으로 봤다. **사건 라벨의 기준은 두 읽기의 사이**에 있다.
- 라벨 '없음' 48건 중 12건에서 에이전트가 엄격 기준으로도 후속 기사를 찾았다(예: 산청·가평 '복구비 6362억 편성', 울산화력 '경찰, 9명 입건', 광주·전남 '농작물 피해조사 착수'). 라벨러가 본 표본(사건당 약 40건) 밖이거나, 정치인의 '당부' 처럼 기관 조치로 볼지 갈리는 경우다.

| 판정 (사건: 후보 중 하나라도 '예') | '있음' | TP | FP | FN | precision | recall | F1 | 라벨과 일치 κ |
|---|---|---|---|---|---|---|---|---|
| 지금 규칙 | 53 | 33 | 20 | 9 | 0.623 | 0.786 | 0.695 | 0.36 |
| 에이전트 엄격 | 35 | 23 | 12 | 19 | 0.657 | 0.548 | 0.597 | 0.30 |
| 에이전트 넓게 | 67 | 38 | 29 | 4 | 0.567 | 0.905 | 0.697 | 0.29 |
| 규칙 그리고 에이전트 넓게 (사건 단위) | 49 | 32 | 17 | 10 | 0.653 | 0.762 | 0.703 | 0.40 |
| 규칙 또는 에이전트 엄격 | 59 | 36 | 23 | 6 | 0.610 | 0.857 | 0.713 | 0.37 |

글을 읽고 판단하는 독립 판정(LLM 판정에 가까운 것)도, 규칙과 섞어도 사건 라벨에 대해 F1 0.71 을 넘지 않았고 라벨과의 일치(Cohen κ)는 0.29~0.40 이다. **사건 라벨 자체의 기준이 글만으로는 재현되지 않는 폭이 크다** — 이것이 0.80 의 가장 큰 병목으로 보인다(같은 지침의 1차·검증 라벨끼리의 0.923 은 검증자가 1차 판정과 근거를 보고 고친 값이라 독립 일치가 아니다).

**⑥ 에이전트 판정으로 기사 정답을 늘려 다시 학습** (학습용 정답만 바꾸고, 평가는 그대로 사건 라벨 90건)

| 기사 정답 | 양성 | 학습에서 뺀 기사 | 로지스틱 회귀 (기본 / 나누기 6가지) | 그래디언트 부스팅 (기본 / 6가지) |
|---|---|---|---|---|
| 근거·전재 = 1, 나머지 0 | 89 | 0 | 0.649 / 0.646 ± 0.015 | 0.686 / 0.672 ± 0.023 |
| + 에이전트 엄격 '예' 를 1로 ('없음' 사건의 '예' 는 뺌) | 217 | 48 | 0.687 / 0.667 ± 0.018 | 0.684 / 0.668 ± 0.019 |
| + 에이전트 넓게 '예' 를 1로 | 339 | 168 | 0.672 / 0.657 ± 0.024 | 0.625 / 0.664 ± 0.024 |

양성을 2.4~3.8배로 늘려도 사건 F1 은 0.65~0.67 에 머물렀다 — 기사 단위 정답을 늘리는 것으로는 사건 라벨과의 어긋남(⑤)이 줄지 않는다.

**⑦ 규칙과 학습 점수를 섞기** (모두 중첩 교차검증 — 문턱은 학습 fold 안쪽 점수로 고르고, 사건 나누기 6가지로 되풀이)

| 방법 | 기본 나누기 F1 (P / R) | 나누기 6가지 평균 |
|---|---|---|
| 지금 규칙 | 0.695 (0.623 / 0.786) | – |
| 학습 점수만 (사건 최댓값) | 0.667 (0.536 / 0.881) | 0.665 ± 0.011 |
| 규칙이 양성으로 본 후보만 다시 채점 | 0.690 (0.667 / 0.714) | 0.678 ± 0.011 |
| (규칙 그리고 점수 ≥ t1) 또는 점수 ≥ t2 | 0.710 (0.647 / 0.786) | 0.691 ± 0.021 |
| **규칙 그리고 (원천 발언이 다짐 또는 점수 ≥ t)** | **0.736 (0.711 / 0.762)** | **0.709 ± 0.018** |
| 같은 혼합, 에이전트 엄격 정답으로 학습 (그래디언트 부스팅) | 0.706 (0.698 / 0.714) | 0.704 ± 0.019 |
| 사건 단위 작은 로지스틱 회귀 (규칙·점수·원천 발언 유형 등 10개) | 0.681 (0.633 / 0.738) | 0.643 ± 0.025 |

- 가장 나은 것은 "다짐 발언(규칙이 잘 맞는 쪽)은 규칙 그대로, 지시·설명 발언은 학습 점수가 높을 때만" 이다. 기본 나누기에서는 0.736(틀린 '있음' 20 → 13)이지만 나누기를 바꾸면 평균 0.709 — 지금 규칙(0.695)보다 0.01 남짓 높고, 나누기 사이 흔들림(± 0.018)보다 작다.
- 학습 없이 규칙만으로 같은 효과를 내 보려 했다(지시·설명 발언이면 원천 발언 자체를 약속으로 본 규칙 판정도 맞아야 함). 원천 발언이 길어 거의 모든 후보가 겹침 조건을 넘어 걸러지지 않았다(F1 0.695 그대로).

**⑧ 어디까지 갔나 — 0.80 에는 닿지 못했다**

| 사건 라벨 90건 기준 | F1 |
|---|---|
| 지금 규칙 (제품, rules-v3) | 0.695 |
| 가장 나은 학습 — 규칙 그리고 (원천 발언이 다짐 또는 학습 점수 ≥ t), 기본 나누기 | 0.736 |
| 같은 방법 — 사건 나누기 6가지 평균 | 0.709 ± 0.018 |

- **결정**: 제품 판정은 지금 규칙 그대로 둔다. 가장 나은 혼합의 이득(나누기 평균 +0.014)이 나누기 사이 흔들림(± 0.018)보다 작고, 제품에 학습 모델과 추가 피처 계산을 얹어야 하기 때문이다(넣을지는 사용자 결정). 실험 DB·대시보드·README 수치는 바뀌지 않았다.
- **0.80 으로 가는 길로 보이는 것**: 사람이 "엄격(원천 발언의 그 조치)" 과 "넓게(그 사건에 대한 기관 대응)" 중 하나를 서면 기준으로 정하고, 원천 발언 뒤 후보 전체(판정 범위 사건당 평균 55건, 적어도 상위 16건)를 보며 사건 라벨을 다시 붙인 뒤 같은 잣대로 다시 재는 것. 지금 라벨로 0.80 을 맞추려면 라벨러의 표본 범위·'당부' 처리 같은 습관을 흉내 내야 하는 것으로 보여 하지 않았다.
- 학습용 기사 정답(에이전트 라벨, 맹검): `backend/gold/followup_article_agent.csv`(855건) · `followup_event_agent.csv`(사건 90건의 원천 발언 조치 요약). 재현: `backend/scripts/train_followup_pairs.py --extract --cv` → `reports/followup_pairs_cv_20261026.md`, 교차 인코더 `backend/scripts/train_followup_cross.py`.

**⑨ 자문 답과 검증 — 0.80 은 이 라벨의 측정 상한 밖으로 보인다**

자문 세션의 답 두 개가 위 결과 뒤에 왔다. 첫 답은 "사건 안 음성을 만드는 기사 단위 라벨링(7갈래: 완료·진행·새문제·같은 사건 다른 조치·응급대응 마무리·사건 보도·다른 사건) + (약속, 기사) 쌍 모델이면 0.76~0.83" 이었고, 둘째 답은 맹검 결과(⑤)를 보고 "기사 라벨이 사건 라벨과 같은 기준이라는 가정이 깨졌다 — 정당하게 갈 수 있는 곳은 0.72~0.75, 병목 보고로 마무리하고 선택지를 사용자에게 올려라" 로 고쳤다. 자문이 제시한 증거는 지금 DB·10-23 라벨 시트(커밋 d99ad86)·10-23 DB 백업으로 다시 셌다.

## 6. 한계

- **에이전트 라벨**: 모든 라벨은 Claude 에이전트가 붙였다. 사람이 다시 보면 수치가 달라질 수 있다. 학습 모델은 에이전트 지침의 경계를 배운다.
- **선택 편향**: 원천 기사는 인용문 검색 상위 표본(108구간 × 200건)에서 골랐고, 질의 건수 400건 안으로 좁혀지는 사건 쪽으로 기울었다(전국 단위 대형 재난보다 시설·지역이 특정되는 사건). 90건은 모집단 전수가 아니다.
- **녹화 재생**: 연결이 바뀌면 약속이 달라지고 새 재검색 질의가 생긴다. 실 API 를 쓰지 않은 단계에서는 녹화에 없는 질의를 건너뛰고 이전 후보로 진행했다.
- **기사 텍스트 범위**: 제목·하이라이트 200자·키워드만 본다. 본문 깊숙이 있는 후속 내용은 보지 못한다.
- **규칙 어댑터**: LLM 이 아니라 표현과 단어 겹침으로 판정한다. 같은 사건의 다른 조치나 일반 복구 기사를 약속의 진행과 구별하기 어렵다.
- **사건 수**: 사건 라벨이 90건이라 후속보도 지표에서 1~2건 차이는 잡음 수준이다.
- **사건 라벨의 기준**: 같은 글을 읽은 독립 판정(맹검 에이전트)과 사건 라벨의 일치가 κ 0.29~0.40 이다. 라벨러는 사건당 약 40건의 표본을 보았고, '엄격(원천 발언의 그 조치)' 과 '넓게(기관 대응 전반)' 사이에서 사건마다 다르게 판단한 흔적이 있다. 후속보도 F1 이 0.70 근처에서 멈추는 가장 큰 이유로 보인다(3.8 ⑤·⑧).

## 7. 남은 과제

- **사람 라벨로 다시 재기** — 최소한 사건 라벨 90건. 지금 수치는 모두 에이전트 라벨 기준이고(사건 라벨의 실질 상한 F1 0.92 언저리, 2.1), 2단계에서는 1~2건 차이가 F1 0.007~0.03 을 움직인다. 3.8 에서 보듯 **기준을 서면으로 정하고(엄격 또는 넓게) 원천 발언 뒤 후보 전체를 보며** 붙여야 F1 0.80 같은 목표를 잴 수 있다 — 판정 범위 후보는 사건당 평균 55건(상위 16건만 보면 1,440건 안팎).
- **후속 신호를 문장 의미로 판정하기** — 남은 틀린 '있음' 의 대부분은 '같은 사건의 응급 대응·다른 조치' 를 '약속한 조치의 진행' 으로 읽은 경우다. 규칙과 작은 분류기로는 더 가르지 못했다. LLM 키가 생기면 약속 추출·후속 신호를 LLM 으로 바꾸고 같은 잣대(사건 90건 · 근거까지 맞은 탐지)로 비교한다. 다만 3.8 의 맹검 에이전트 판정(LLM 판정에 가까움)도 지금 라벨에 대해 F1 0.60~0.71 이었으므로, 라벨을 다시 붙이기 전에는 LLM 으로 바꿔도 큰 폭의 개선은 기대하기 어렵다.
- **약속이 없는 사건** — 원천 발언이 요구·설명이라 추적할 약속이 없는 사건 14건(라벨 '있음' 3건: 의성 산불·융건릉·국정자원)은 지금 방식으로 찾을 수 없다.
- **검토 대기·미연결 근거** — 라벨 근거 기사가 검토 대기이거나 연결되지 않은 '있음' 사건 2건(공주, 구로역)은 1단계 수집·연결 몫이다(예천·봉화는 재순위 뒤 다른 근거로 찾는다).
- **공공기관 게시판 확인 다시 돌리기** — 상태가 바뀌어 조건에 드는 사건이 19건 → 31건이 됐다. 네트워크가 필요한 별도 기능이라(공공기관 공식 게시판, robots.txt·2초 간격) 이번에는 돌리지 않았다. 발표 전에 `run_notices.py --all` 로 다시 맞춘다.
- **다음 날 응급 대응 보도** — 기준일을 원천 발언 다음 날로 당기며 되찾은 후속(철거 완료·안전진단 추진)과 함께, 수색·감식·압수수색 같은 다음 날 보도가 틀린 '있음' 의 새 원천이 됐다.
