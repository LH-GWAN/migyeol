# 시연 대본 (3분) — 목록 → 타임라인 → 근거 확인

> 예선 목업 기준. 본선에서는 시연용 실제 사건 3건(완료 1 · 진행 1 · 후속보도 부족 1)으로 교체한다.
> 시연 전 `BIGKINDS_MODE=record` 로 캐시를 채워 두면 네트워크 없이 같은 화면이 나온다.

## 0. 준비 (시연 전)
```bash
cd backend && TODAY_OVERRIDE=2026-09-11 .venv/bin/python scripts/run_pipeline.py --stage all --reset
.venv/bin/uvicorn app.main:app --port 8000
cd ../frontend && npm run dev -- -p 3000
```
브라우저 http://localhost:3000 — 우측 상단 `데이터: 빅카인즈 API (mock)` 확인.

## 1. 후속 확인 필요 목록 (40초)
- "뉴스는 최신순으로 정렬됩니다. 미결은 **미완결성** 순으로 정렬합니다."
- 맨 위 카드 **누리군 청솔산 산사태**: 발표된 기한 `2026년 6월` 이 지났는데(기한 경과 73일) 마지막 후속 기사가 9개월 전 → `후속보도 부족`. "이 카드 자체가 기자에게는 후속 취재 목록입니다."
- 두 번째 **가온시 남문시장 가스폭발**: `조치 진행 정황 확인` 인데도 상단인 이유 — 기한(3월)이 지났고 마지막 기사가 "5월 완료 예정". "**완료 예정은 완료가 아닙니다.** 시스템은 이를 진행으로만 표시합니다."
- "확인 필요만 보기"를 끄면 `조치 완료 근거 확인` 사건이 아래에 보인다 — 완료된 사건은 뒤로 간다.

## 2. 사건 타임라인 (60초)
- **가온시 달빛지하차도 침수 사고** 클릭.
- 5단계 스텝: 발생(3) → 원인조사(1) → 대응발표(2) → 조치진행(비어 있음: "이 단계의 보도를 찾지 못함") → 결과확인(비어 있음).
- 대응발표의 약속 카드: 주체 `가온시` / 행동 `배수펌프 용량을 2배로 증설` / 기한 `2026년 10월` / 발언 강도 `확약`, 원문 인용문과 근거 기사. 같은 발언의 "차단시설 설치"는 `계획`, 국장의 "노력하겠다"는 `의사표명` 으로 추적 대상에서 제외됨을 보여준다.
- 보도량 차트: 발생 직후 급증 → 급감, 세로선(발생·기한·오늘). "보도는 사라졌지만 기한은 아직 오지 않았습니다. 그래서 상태는 후속보도 부족이지 불이행이 아닙니다." ← 이 문장에서 **단정하지 않는 표현 원칙**을 강조.

## 3. 근거·불확실성 (50초)
- "근거 보기" 클릭.
- 판정 규칙 상자: `R4_stale_followup — 마지막 후속 기사가 83일 전(기준 60일)이고 완료·진행 신호가 없음`, 임계값 표시.
- 신호 표: 2건 모두 `불명확` — 발췌 문장 "착공 시점은 정해지지 않았다", "절차를 진행 중이라고만 답했다" 와 신뢰도. "AI 가 결론만 내지 않고 어떤 문장 때문에 그렇게 판단했는지 보여줍니다."
- 다음 자동 재조회 시각, 면책 문구.
- **누리군 해맞이터널 붕괴** 근거 화면으로 이동: `R2 완료 신호 1건(신뢰도 0.90)` 과 발췌 "전 구간 라이닝 보강을 완료했으며". 저신뢰 연결 목록에 **달빛터널 낙석** 기사 → "잘못된 연결 신고" 클릭 → 관리자 화면에서 해제. "사람이 고친 연결은 다시 자동 연결되지 않습니다."

## 4. 마무리 (20초)
- "빅카인즈 API 7개를 하나의 사건 추적 파이프라인으로 묶었고, 본문 전문은 어디에도 저장하지 않습니다."
- "본선에서는 실제 사건 20~30건, 정답셋 30건으로 연결·추출·판정 정확도를 측정해 임계값을 정합니다."

## 예상 질문
- **보도가 없으면 안 한 것 아닌가?** → 아닙니다. 상태는 `후속보도 부족` 이고 화면 어디에도 `미이행` 은 없습니다. 보도 공백은 확인이 필요하다는 신호입니다.
- **같은 지역 비슷한 사고가 섞이지 않나?** → 규칙 게이트(지역·시설·기관 + 사건분류/키워드) 뒤에 임베딩 점수로 경계 사례를 검토 큐로 보내고, 사용자 신고와 관리자 확정으로 고정합니다.
- **LLM 이 틀리면?** → LLM 은 약속 추출과 후속 신호 분류 두 역할만 하고, 근거 문장이 입력에 없으면 코드가 `불명확` 으로 강등합니다. 상태 판정은 규칙이며 규칙 이름과 임계값이 화면에 나옵니다.
