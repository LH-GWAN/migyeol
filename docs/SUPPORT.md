# 민간 지원 소식 — 규칙·주체 판별·실행·수치

> 코드 `backend/app/support/`(extractor·service·models), 어휘 `backend/app/rules/support_terms.py`, 실행 `backend/scripts/run_support.py`,
> API `GET /api/events/{id}/support`, 화면 `frontend/src/components/support/SupportPanel.tsx`(근거 화면, 「기관 발표 확인」 패널 다음).
> 테스트 `backend/tests/test_support_extractor.py`·`test_support_api.py`.

## 1. 무엇을 보여 주나 — 사건 타임라인의 세 번째 주체

사건 상세에는 언론(연결 기사 → 후속보도 신호)과 공공기관(기관 게시판 발표)의 흐름이 있었다. 여기에 **민간(기업·단체·개인)의 지원 소식**을
같은 틀로 붙인다: **사건 발생 → 기관 발표 → 민간 지원 소식 → 후속보도 확인**. 별도의 '기업 칸'이나 광고 성격의 칸은 만들지 않는다 —
사고 당사자 기업이 돈을 내고 홍보하는 자리로 보이면 신뢰를 잃기 때문이다. 대신 연결 기사에서 **사실만** 뽑아 날짜·주체·지원 어휘·근거 문구·기사
링크로 보여 준다. 주체를 치켜세우는 평가 단어는 화면·문서·코드 어디에도 쓰지 않는다(테스트로 고정).

- 보조 근거다. 사건 상태(5종)와 상태 판정(`rules/status.py`·`pipeline/judge.py`)은 건드리지 않는다.
- 언론사 원문은 읽지 않는다. 입력은 이미 저장된 `articles` 행의 빅카인즈 메타데이터(제목·hilight·content_200·tms_keywords)뿐이다.
- 사건 설명에 이름이 들어 있는 주체는 숨기지 않고 「사건 당사자」 칩으로 표시한다(§3).

## 2. 추출 규칙 (`support/extractor.py`)

| 단계 | 규칙 |
|---|---|
| 입력 | 사건의 활성 연결 기사(`EventArticle.is_active`: `rejected`·`needs_review` 아님) 중 **발생일 이후** 기사. 제목·hilight·content_200 을 문장으로 나눈다(hilight 의 `..` 생략 표시도 경계) |
| 기사 관련성 | 제목+발췌+본문 200자+핵심어에 사건 관련어(피해·이재민·복구·수해·유가족·희생자·구호·재난·재해·참사·부상자·사망자·실종자·상인·침수·수습) 가 하나도 없으면 보지 않는다 — 연결된 기업 홍보 기사(연말 봉사 등) 제외 |
| 지원 어휘 | `SUPPORT_TERMS`: 성금·성금 전달·기부·기부금·후원금·후원 물품·지원금·위로금·조의금·구호물품·구호품·구호물자·구호 키트·긴급구호·복구 지원·의료 지원·무상 지원·무상 수리·물품 전달·생필품·자원봉사·봉사활동·기탁. 문장 안에 있어야 한다. `SUPPORT_MASKS`(기부채납·재난지원금·재해구호기금·후원사·자원봉사센터·봉사단 …)는 먼저 가린다. 두 글자 '기부' 는 어절 첫머리(또는 재능·현금·물품 뒤)에서만 센다('경기부지사'·'중기부'·'2분기부터' 제외) |
| 부정 문장 | 촉구·요구·요청·건의·주장·비판·논란·의혹·횡령·유용·사기·사칭·체불·거부·반발·수사·압수수색·기소·표창·수상·시상·포상·감사패·공로·고발·고소·지원받·지급받·지급·고용유지 가 있는 문장은 지원 행위가 아니다 |
| 주체 후보 | 토큰 단위. **기업** = 접미(㈜·주식회사·그룹·은행·저축은행·카드·손해보험·생명보험·증권·캐피탈·건설·전자·화학·제약·마트·물산·중공업·자동차·텔레콤·백화점·홈쇼핑·타이어·제철·홀딩스·리테일·코리아·컴퍼니·바이오·인프라코어·엔터테인먼트·면세점·편의점 …) 또는 상호 접두(KT·SK·LG·GS·CJ·삼성·롯데·한화·포스코·두산·신한·카카오·네이버·쿠팡·현대차·현대위아·더본코리아·BGF·아모레… `CORPORATE_PREFIXES`). **단체** = 접미(재단·법인·협회·연합회·적십자(사)·구세군·봉사단·봉사회·봉사센터·라이온스·로타리·종친회·향우회·재향군인회·장애인회·노인회·부녀회·청년회·동문회·산악회·조합·협동조합·산림조합·새마을금고·신협·농협·수협·축협·상공회의소·중앙회·연맹·교회·성당·사찰·교구·교단·병원·학회·협의회·번영회·자율방재단·새마을회·노동조합·노조·노총) 또는 단체 접두(희망브리지·전국재해구호협회·굿네이버스·월드비전·세이브더칠드런·유니세프·기아대책·해비타트·대한적십자사·농협·수협·신협·새마을금고). 접미 앞이 일반어(`GENERIC_STEMS`: 중소·지역·민간·자원·청년·피해·사고 …)면 상호가 아니다. 상호 접두 뒤가 지명 꼬리(동·역·로·강·시장·학교 …)면 지명이다('삼성동'·'금호강'·'현대시장') |
| 공공 제외 | `rules/actors.is_public_actor`(정부·지자체·공사·공단·소방·경찰 …)가 참이면 제외 — 공공기관의 지원은 '기관 발표' 영역. 공직자 모임·의회·정당(시장군수협의회·군수구청장협의회·의회의장협의회·의원·공무원·공직자·교섭단체·시당·도당·당원·정당 이름)도 공공 영역으로 보아 제외. 공공 조직 산하 단위('경기도의료원 ○○병원', 서울대·국립·도립 병원)도 제외 |
| 모금 창구 제외 | 공동모금회·모금회·사랑의열매는 기부자가 아니라 전달 경로 — 주체로 보지 않는다 |
| 수혜·경유 제외 | '…에', '…에게', '…를 통해', '…로 전달', 'X 회장에게', '적십자사 충남지사에', '희망브리지 전국재해구호협회에' 처럼 수혜·경유 조사가 붙은 이름(과 그 지부)은 제외 |
| 주어 판정 | 주체는 문장의 주어여야 한다: 주격 조사(은·는·이·가·에서·도·측) 또는 쉼표(제목 'X, …'), 'X 임직원 50여명이'·'X 등 기업들은'·'X 및 Y는' 같은 연쇄(4토큰 이내), 'X 홍길동 대표가', 제목 첫머리(앞이 지역명뿐일 때). 'A과 B' 는 연쇄가 주격으로 끝날 때만 공동 주어('농협과 지역농축협 계좌에' 는 아니다) |
| 사건 설명 속 이름 | '금호타이어 광주공장 화재'·'제주항공 참사'·'HD현대삼호 화재,' 처럼 다음 토큰(또는 시설어 + 다음 토큰)이 사고 어휘면 주체가 아니다. 사건 당사자 이름(§3)은 제목 첫머리 규칙을 쓰지 않고 조사·쉼표·연쇄로만 주어를 인정한다 |
| 이름 만들기 | 앞의 지역명을 붙인다('인천 새마을금고'); 접미만 있는 토큰은 앞 토큰과 합친다('아이다움 봉사단', '평해구씨 대종친회', '농·축협'); 뒤의 지부·지점을 붙인다('신한은행 인천기관본부', 'NH농협 서천군지부'); 캡션이 붙은 토큰은 상호 앞을 잘라낸다('사진=인천시청NH농협은행' → 'NH농협은행'); 같은 기사에서 한 이름이 다른 이름에 포함되면 긴 쪽만('대한적십자사'·'적십자사', 'KB국민은행'·'국민은행', 'IBK기업'·'IBK기업은행') |
| 개인 | 기업·단체가 없고 '…씨가/는'(성씨 + 1~3자, 수혜 조사 아님)·'익명'·'독지가' 가 지원 어휘와 같은 문장에 있으면 `actor_kind=개인`. **이름은 저장하지 않고 '개인'으로만 적는다**('불씨는'·'날씨' 는 사람이 아니다) |
| 근거 문구 | 주체와 어휘가 함께 있는 문장(hilight·content 우선, 제목은 마지막) ≤ 200자 — 메타데이터 범위 안 |
| 저장 | `support_mentions`(event_id, news_id, actor, actor_kind 기업\|단체\|개인, actor_role 당사자\|제3자, support_terms JSON, evidence_span, published_at, created_at). **(event_id, news_id, actor) 유일** — 같은 기사에 주체가 여럿이면 여러 행 |

tms_keywords 는 기사 관련성 판정에 쓴다(핵심어에 피해·복구 등이 있으면 관련 기사). 조직명 후보는 제목·발췌 토큰에서만 뽑는다 — 핵심어의 짧은 이름('국민은행'·'구호협회')은 같은 기사의 긴 이름과 중복만 만들었다.

## 3. 당사자 표시

주체의 핵심 이름(공백 제거, 2자 이상)이 사건 설명 — 제목·요약·시설명·책임기관·핵심어·기관 별칭(공백 제거) — 에 들어 있으면 `actor_role=당사자`, 아니면 `제3자`.
화면에는 「사건 당사자」 칩으로 **사실만** 표시한다(숨기지도, 평가하지도 않는다). 예: 금호타이어 광주공장 화재 사건에서 '금호타이어 직원들이 광주공장 인근에서 청소 자원봉사' → 금호타이어 · 기업 · 사건 당사자.
당사자 기업이 사건 설명의 일부로만 나온 문장('금호타이어 광주공장 화재로 피해를 입은 …')은 주체로 뽑지 않는다(§2 사건 설명 속 이름).

## 4. 실행

```bash
cd backend
.venv/bin/python scripts/run_support.py --all            # 활성 사건 전체 — support_mentions 를 지우고 다시 만든다 (멱등, 외부 요청 없음)
.venv/bin/python scripts/run_support.py --event 164      # 한 사건만 (--event-id 도 같다)
.venv/bin/python scripts/run_support.py --all --dump     # 저장 행을 JSON 줄로 함께 출력 (정밀도 표본 읽기용)
```

파이프라인 runner 에는 넣지 않았다(규칙만 바뀌어도 `--all` 로 재생성하면 된다). 실험 DB 는 `BIGKINDS_MODE=record BIGKINDS_REPLAY_ONLY=true LLM_MODE=rules EMBEDDING_BACKEND=st TODAY_OVERRIDE=2026-10-22` 로 돌린다. `init_db` 가 `support/models.py` 를 import 하므로 기동 때 테이블이 만들어진다.

## 5. API·화면

- `GET /api/events/{id}/support` (공개, 외부 요청 없음): `{ event_id, count, actors, items: [{news_id, title, published_at, provider, provider_link_page, actor, actor_kind, actor_role, support_terms, evidence_span}], note, disclaimer }`. `items` 는 게시일 오름차순(타임라인). `disclaimer` = "연결 기사에서 규칙으로 뽑은 지원 언급이며 사건 상태와 무관합니다".
- 근거 화면 `/events/[id]/evidence`: 「기관 발표 확인」 패널 다음에 「민간 지원 소식」 패널(앵커 `#support-heading`). 행 = 날짜 · 주체(종류 칩, 당사자면 「사건 당사자」 칩) · 지원 어휘 칩 · 근거 문구 · 기사 제목(`provider_link_page` 가 있을 때만 링크) · 언론사. 8건까지 펼치고 나머지는 「나머지 N건 보기」. 없으면 "연결 기사에서 확인된 민간 지원 언급이 없습니다" 한 줄.

## 7. 한도와 주의

- 규칙 추출이라 **재현율은 낮다**: 접미·접두 목록에 없는 상호(예: '한컴'·'앤하우스' 는 그룹·㈜ 덕에 잡혔지만 접미 없는 중소기업명은 놓친다), 주격 조사 없는 문장, 생략된 발췌(`..`)는 놓친다. 셀 수 있는 것은 정밀도뿐이고 재현율은 재지 않았다.
- 같은 사건의 같은 주체가 기사마다 한 행씩 쌓인다(신한은행 1억 기탁이 18개 매체 → 18행). 화면은 8건까지 펼치고 나머지는 접는다. 행을 주체별로 묶는 것은 다음 보강 대상.
- 자원봉사센터·자율방재단·새마을회는 지자체가 지원·위탁하는 민간 봉사 조직이라 '단체'로 둔다. 공단·공사의 임직원 봉사단('희망새미봉사단')처럼 공공과 민간 사이의 조직은 단체로 남는다.
- 당사자 표시는 사건 설명에 이름이 있을 때만 붙는다. 설명에 시공사·운항사 이름이 없으면(예: 청라 전기차 화재의 제조사) 제3자로 보인다 — 시드 요약에 이름을 적으면 바로 당사자로 바뀐다.
- 금액·물품 수량은 저장하지 않는다(근거 문구에 그대로 보인다). 금액 합산·기업별 집계('ESG 추적 리포트')는 이 테이블 위에 만들 다음 단계다.
