## 1. 규칙 요약

| 항목 | 내용 |
|---|---|
| 트리거 | 상태가 `후속보도 부족`·`판단 불가`(판정된 사건만)이고 `max(마지막 후속 기사일, 가장 늦은 약속 발언일, 발생일)`로부터 `NOTICE_TRIGGER_DAYS`(90)일 이상. **트리거되지 않은 사건은 robots.txt 를 포함해 어떤 요청도 보내지 않는다**(테스트 고정) |
| 대상 | 사건 `responsible_org` → `rules/orgs.canonical_org()` → 등록부에서 그 기관을 맡은 게시판만 |
| 읽는 범위 | 목록 페이지의 제목·게시일·URL(사이트당 최대 `NOTICE_MAX_PAGES`=5쪽, 발생일 이전 글만 남으면 멈춤). 게시판 자체 제목 검색이 있으면 시설명·핵심어로 검색 목록을 읽는다(같은 쪽수 예산). 제목이 매칭된 항목만 상세 본문 첫 300자(또는 목록 요약). 첨부·이미지·전체 본문 저장 없음 |
| 요청 예절 | 같은 호스트 요청 간격 `NOTICE_REQUEST_INTERVAL_SEC`(2초) 이상, User-Agent `NOTICE_USER_AGENT`, robots.txt 준수(RFC 9309: 최장 일치·Allow 우선, 4xx=제한 없음, 5xx·연결 실패=접근 안 함), 리다이렉트는 한 단계씩 다시 검사, HTML 아닌 응답·3MB 초과 거부 |
| 도메인 | 허용 = `NOTICE_ALLOWED_DOMAINS`(.go.kr, .or.kr, korea.kr) + 등록부 도메인. **뉴스 도메인(언론사·방송·포털 뉴스·빅카인즈 웹)은 허용 접미에 걸려도 코드에서 거부**(`guard.NEWS_DOMAINS`, 등록부 로드 시에도 거부) |
| 매칭 | 제목 토큰 겹침을 **용어 특정성**에 따라 가중(§1-1): 고유 시설명 0.6, 일반어 구 0.4, 고유 핵심어·약속어·지역명 0.3, 일반어 단일 0.2 + 가점(조치 어휘·발생 직후·요약 각 0.1), 합 상한 1.0. `≥ NOTICE_MATCH_THRESHOLD`(0.5)만 `org_notices` 에 저장하고 `Event.org_notice_found=true`. 규칙이 바뀌면 `--rescore` 로 저장분을 다시 매긴다(§6) |
| 의미 | 보조 근거. 5개 상태를 바꾸지 않는다. 근거 화면 「기관 발표 확인」 패널·보도자료 초안에 제목·날짜·링크로 표시 |
| 기록 | 실행마다 `notice_checks`(트리거 여부·사유·결과 `not_triggered/no_site/found/not_found/error`·게시판별 쪽수·항목 수·오류·요청 수) |

### 1-1. 매칭 규칙 (2026-10-27 보강 — `matcher.py`)

2026-10-23 수집분은 시설명 한 단어(0.6)만 맞으면 저장돼 잡음이 많았다(사건 171 '송전선' 19건 중 15건이 송전선로 공사·해저케이블·외국인력 글). 용어를 **고유어/일반어**로 나누고, 일반어만 맞은 제목은 **조치 어휘**가 있어야 넘도록 바꿨다.

| 구분 | 판정 | 가중치 | 예 |
|---|---|---|---|
| 고유 시설명 | 정규화 4자 이상이고 일반어 목록에 없는 단어가 있는 시설명 (숫자가 들면 길이 무관) | **0.6** — 단독 저장 | 통복터널, 달빛지하차도, 4대강 |
| 일반어 구 | 두 단어 이상이 모두 일반어(3자 이하·또는 `GENERIC_WORDS`)인 용어, 종류 무관 | 0.4 — 단독으로는 못 넘음 | 하천 제방, 지하차도 침수, 태풍 카눈 |
| 고유 핵심어·약속어 | 일반어가 아닌 핵심어(`keywords`)·약속 행동 키워드(`promise_terms`) | 0.3 | 유관기관, 배수펌프, 5호선 |
| 지역명 | 사건 `region` 어간('군위군'→'군위'). 책임기관 자신의 이름(서울시 사건의 서울시)이면 쓰지 않음 | 0.3 | 군위, 부평, 대전 |
| 일반어 단일 | 정규화 3자 이하(숫자 없음) 또는 `GENERIC_WORDS` | 0.2 | 열차, 사고, 산불, 한전, 송전선 |
| 가점 ① 조치 어휘 | 제목에 `ACTION_WORDS`(점검·보강·복구·대책·조치·정비·준설·설치·강화·예방·대비·대응·안전·착공·준공·완료·훈련·긴급·수사·조사·규명·과징금 …) | +0.1 | '제방 등 국가하천 시설 **점검**' |
| 가점 ② 발생 직후 | 게시일이 발생 전날~7일 뒤 | +0.1 | 5호선 방화 당일 서울시 긴급 지시 |
| 가점 ③ 요약 | 목록 요약(snippet)에 제목에 없는 지역명 또는 고유 시설명 | +0.1 | 요약에 '군위군' |
| 감점 다른 지역 | 제목에 사건 지역(사건 `region`·그 광역·지자체 책임기관)이 아닌 행정구역 이름(`rules/regions.ADMIN_BASES`, 보통명사와 겹치는 이름 제외). 고유 시설명이 맞은 제목은 감점 없음 | −0.3 | 옹진 어선 전복 사건에 '제주해역 어선 전복 긴급지시' → 0.2 |

가점은 **시설명·지역명·고유어 중 하나가 제목에 맞았거나, 사건 지역 어간(`region`·그 광역·지자체 책임기관, 예 여수·전남·인천)이 제목이나 요약에 있을 때만** 붙는다(제목 기반 원칙). '열차'·'사고'·'호우'·'긴급' 같은 일반어 단일 용어나 '어선 전복'·'청라 전기차 화재' 같은 일반어 핵심어 쌍만 맞은 제목은 지역명이 없으면 둘이 맞아도 0.4 이고 가점이 없어 저장되지 않는다 — 같은 종류의 다른 사고 발표(코레일 사건에 다른 열차 사고 복구 글, 대덕구 낙석 사건에 국무총리 호우 긴급지시, 여수 통발어선 사건에 전국 어선 안전관리 대책)가 들어오는 것을 막는 규칙(2026-10-27 2차·4차). 시설명이 일반어 구('하천 제방'·'태풍 종다리')여도 시설명이 맞으면 지역명 없이 가점을 받는다. 그 밖에: 여러 단어 용어는 모든 단어가 제목에 있어야 일치 · 3자 이하 용어는 띄어쓰기 없이 그대로 있어야 일치('벤처 4대 강국' ≠ '4대강') · 긴 용어에 포함된 짧은 용어는 중복으로 세지 않음 · 발생 전날 이전 글 제외는 그대로.

임계값 0.5 를 넘는 조합(대표): 고유 시설명 단독 / 고유 핵심어·약속어 둘 / 일반어 구 시설명 + 조치 어휘('하천 제방' + 점검) / 일반어 시설명 + 일반어 핵심어 + 조치 어휘('송전선' + 산불 + 점검) / 일반어 핵심어 쌍 + 제목·요약의 지역 어간 + 조치 어휘('어선 전복' + 여수 + 긴급) / 일반어 둘 + 지역명 / 일반어 셋. 넘지 못하는 조합: 일반어 시설명 단독(송전선), 일반어 둘·일반어 핵심어 쌍만(열차+사고·호우+긴급·'어선 전복' — 지역명이 없으면 조치 어휘가 있어도 0.4), 고유 핵심어 하나 + 조치 어휘(0.4).

저장되는 `matched_terms` 는 일치 용어 뒤에 가점을 `+조치 어휘: 점검`·`+발생 7일 내`·`+요약: 군위`, 감점을 `−다른 지역: 제주` 로 붙인다(화면 칩으로 그대로 보인다).

## 4. 실행

```bash
cd backend
.venv/bin/python scripts/run_notices.py --all                # 활성 사건 전체 — 트리거된 사건만 요청
.venv/bin/python scripts/run_notices.py --event-id 3
.venv/bin/python scripts/run_notices.py --check-sites --query 안전 --detail   # 등록부 점검 (이 문서의 표)
.venv/bin/python scripts/run_notices.py --rescore --dry-run                   # 저장된 org_notices 를 현재 규칙으로 다시 매긴 결과만 본다 (요청 0건)
.venv/bin/python scripts/run_notices.py --rescore [171]                       # 실제 적용: 임계값 미만 삭제, org_notice_found·notice_checks.items_found 정합
```

관리자 API: `POST /api/notices/run {"event_id": 3}` (`X-Admin-Token`). 조회: `GET /api/notices/events/{id}` → `{triggered, reason, state, state_label, checked_at, sites[], items[]}`.

가상 픽스처(가온시·누리군)는 등록부에 없으므로 mock DB 에서는 트리거된 2건(달빛지하차도·청솔산)이 「등록된 게시판 없음」, 나머지 6건이 「트리거 조건 미충족」이고 요청 수는 0이다. 「기관 발표 확인」 경로는 `tests/test_notices_api.py` 가 고정 HTML(가상 가온시 게시판)로 검증한다.

## 5. 한계

- 목록 제목 매칭이라 제목에 시설명·핵심어가 없는 발표는 놓친다(검색 지원 게시판은 시설명 검색으로 보완). 요약 가점은 목록 페이지가 주는 요약에만 적용된다(상세 본문은 매칭된 항목만 뒤에 가져온다) — `--rescore` 는 저장된 요약(본문 첫 300자일 수 있음)으로 매기므로 수집 시점과 점수가 조금 다를 수 있다.
- 일반어 판정은 길이(3자 이하)와 고정 목록이라 짧은 고유명사('카눈'·'한전'·'코레일')도 일반어로 본다. 그런 용어는 둘이 맞아도 0.4 라 조치 어휘가 없으면 저장되지 않는다. 반대로 '열차 사고 복구' 류 제목은 같은 종류의 다른 사고 발표여도 저장된다(사건 11 — 2024~2026 년의 다른 열차 사고 복구 글 13건이 남아 있다). 사건을 특정하려면 발생 지역·시설명이 제목에 있어야 하므로, 핵심어가 일반어뿐인 사건은 사람이 보는 보조 근거로만 쓴다.
- 조치 어휘 가점은 기관 보도자료 제목에 흔한 말이라 변별력이 크지 않다(일반어 둘·일반어 구를 넘기는 용도). '검거'·'행사'·'공모전' 같은 제목은 넘지 못한다. 보도자료가 첨부파일(hwp/pdf)뿐인 게시판은 본문 요약이 비거나 메타데이터만 남는다.
- 목록은 최신순 5쪽까지만 본다. 검색이 없는 게시판(없음 — 12곳 모두 검색 URL 등록)에서는 오래된 사건의 발표가 5쪽 밖일 수 있다.
- 게시판 구조가 바뀌면 선택자가 깨진다 → `--check-sites` 를 시연 전에 다시 돌려 이 표를 갱신한다(항목 0건이면 종료 코드 1).
